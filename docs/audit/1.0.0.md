# 产品工作台 1.0.0 审计

审计日期：2026-10-08（Asia/Shanghai）

版本：**1.0.0**

审计对象：`main` 分支维护的 1.0.0 代码与本次整合修复。

结论：**主要能力已有实现，但还没有完成可用的线上业务闭环验收。应先完成下列核心修复，再扩展功能。**

本文件是唯一的审计结论、验证结果和待办入口。原始证据集中在 `output/audit/1.0.0/`。本文不使用其他批次的测试或审计结论。

## 1. 本次产品范围

用户在网页输入需求，系统结合项目授权的知识，生成对应的需求文档和原型；需求文档可在线阅读并下载 Word/PDF；原型可通过固定版本链接分享和在线交互预览。

| 用户需要的能力 | 当前实现 | 本次判断 |
| --- | --- | --- |
| 在线输入需求、附件和参考资料 | 首页、项目输入框、文件上传、固定来源导入、持久化提交 | 已实现；首页输入法和双产物选择存在问题 |
| 根据知识生成 | ready KnowledgeRelease 固定、授权检索、引用与检索回执校验 | 已实现；首次初始化、项目知识更新和入库语义仍有缺口 |
| 同时生成需求文档和原型 | 后端接受 PRD/Prototype 双产物，固定关联版本 | 已实现协议；界面缺明确的双产物入口，尚无业务覆盖率校验 |
| 文档在线阅读 | PRD 专用渲染、编辑与版本持久化 | PRD 可用；未保存草稿有丢失风险，普通 document 仅展示 JSON |
| Word/PDF 下载 | 导出任务、专用 PRD 渲染、文件读取校验、重试下载 | 已实现且本机真实渲染通过；通用 Markdown 格式转换不完整 |
| 原型在线预览、公开分享 | 独立预览域、固定 Release、分享 token、公开产物读取 | 已实现；公网、真实对象存储和权限变化后的完整验收尚未完成 |

文档在线预览和下载按登录后的项目内使用验收。原型使用公开分享链接；文档对外匿名分享不是本次新增的必要范围。

## 3. 必须优先处理的问题

### F01 · P1 · 文档编辑草稿会无提示丢失

- **位置：** `apps/web/components/workbench/workbench-board-nodes.tsx:712`；`workbench-artifact-content.tsx:260`。
- **触发：**编辑 PRD 后点击画布空白或另一张产物，导致取消选中，再重新选中原文档。
- **本次复现：**将作者改为“审计保留草稿”，编辑状态从 true → false → true 后恢复为“产品经理”；提交接口未调用。取消选中会卸载持有局部草稿的编辑器。
- **相关影响：**发布前只刷新 Board，未统一处理 PRD 脏状态，用户看到的修改可能没有进入导出或发布版本（`workbench-publication-controller.ts:304`）。
- **完成标准：**按项目和产物持久保存草稿；取消选中、导航、预览、发布和导出使用统一的保存/放弃机制；回归覆盖上述操作。
- **证据：** `frontend-probes.json`。

### F02 · P1 · 全新部署缺完整的首次知识初始化路径

- **位置：** `deploy/workbench-compose.yml:244`、`:328`；`apps/workbench-api/src/modules/knowledge/knowledge-readiness.service.ts:66`；`scripts/workbench-knowledge-release-lib.mjs:32`；`scripts/workbench-knowledge-profile-operator-lib.mjs:33`。
- **触发：**在完全空库上按默认生产 Compose 启动。
- **静态链路：**Web 等 API healthy；API ready 要求已有 ready KnowledgeRelease；首次创建并提升知识 profiles 的 API 需要登录授权，而 API 的 JWKS 又由尚未启动的 Web 提供。发布 CLI 要求 profiles 已 adopted，operator CLI 要求 principal 已存在。
- **影响：**缺少独立 bootstrap 时，正常登录和知识配置入口无法自行完成首次引导。
- **边界：**已预置 profiles/operator 的环境可以用独立 File Worker 和发布 CLI 完成知识发布；不存在 API 与 File Worker 的相互等待。未运行生产 Compose，故不据此断言现网故障。
- **完成标准：**提供一个可重跑的首次初始化入口，明确账号、operator、profiles、知识发布及服务启动顺序；用空库部署测试验证。

### F04 · P2 · 没有明确的“需求文档＋原型”生成选项

- **本次复现：**`Enter` 且 `isComposing=true` 时，提交回调仍被调用一次。项目内输入框已经有对应保护。
- **完成标准：**首页复用同等输入法保护，并验证候选词确认、换行和正式发送三种行为。

### F06 · P2 · 定稿入库丢失业务字段和关系

- **位置：** `apps/workbench-api/src/modules/artifacts/artifact-finalizations.service.ts:148`。
- **现状：**通过字段名白名单提取字符串，忽略渠道启用布尔值、安全适用性、图的边关系以及原型动作/状态的结构关系。
- **本次复现：**将 `wapH5.enabled` 从 true 改为 false，同时把安全适用性从“是”改为“否”，生成的知识 Markdown 完全相同。
- **影响：**“入库成功”不代表知识保留了已确认的完整业务含义，后续生成可能依据不完整资料。
- **完成标准：**为 PRD、Prototype 编写按类型的业务序列化；保留表格行列、开关、状态及关系，并验证语义变化必然反映到入库结果。
- **证据：** `generation-probes.json`。

### F07 · P2 · 已有项目缺显式更新知识基线的入口

- **位置：** `apps/workbench-api/src/modules/runs/runs.service.ts:177`；`artifact-finalizations.service.ts:112`；`apps/workbench-file-worker/src/knowledge/prisma-knowledge-build.store.ts:280`。
- **触发：**项目已有定稿派生知识快照，随后更新全局或工作区知识。项目下一次生成仍优先使用自己的快照，继续定稿也沿用该父快照。
- **影响：**知识修订或噪声清理不能自然传播到已有项目。现有 `knowledge:release` 只发布全局/工作区知识，没有保留项目定稿内容并更新其继承基线的命令。
- **完成标准：**提供显式预览差异、合并并发布新项目知识版本的入口；已执行 Run 的固定知识快照保持不可变。级联撤回定稿不是正常更新方案。

### F08 · P2 · 长任务的知识授权可能先于任务时限过期

- **位置：** `apps/workbench-worker/src/config.ts:70`、`:171`；`src/runs/run-processor.ts:368`；`integrations/deerflow/runtime-tools/deerflow_workbench_tools/knowledge_client.py:132`。
- **现状：**默认运行预算 30 分钟，知识授权 900 秒；只在首次 submit 签发，持续执行和 join 没有续期。
- **触发：**运行超过 15 分钟后再次检索知识，工具因授权到期拒绝。此结论来自代码路径，未执行耗时 30 分钟的模型任务。
- **完成标准：**实现受运行状态和权限约束的续期，或校验授权时长覆盖整个运行预算。

### F09 · P2 · 一个损坏导出会导致整页导出列表失败

- **位置：** `apps/workbench-api/src/modules/exports/export.mapper.ts:70`；`exports.service.ts:127`；`packages/workbench-content-security/src/ready-object-prisma.ts:89`。
- **触发：**已成功导出的 Blob 在回读校验中被隔离，ExportJob 仍为 succeeded；mapper 抛 `EXPORT_OUTPUT_BLOB_NOT_READABLE`，整页 `map` 随之失败。
- **本次复现：**对保持 succeeded、输出被隔离的记录调用实际 mapper，确认抛出该异常。
- **完成标准：**表达“已生成但输出不可用”的业务状态，阻止下载并提供恢复入口；一个异常条目不能影响正常记录列表。
- **证据：** `delivery-probes.json`。

### F10 · P2 · 私有预览的签发与访问检查主体不同

- **位置：** `apps/workbench-api/src/modules/exports/exports.service.ts:411`、`:459`；`apps/workbench-preview/src/preview.service.ts:60`。
- **现状：**签发按当前请求者权限检查；访问时检查导出创建者仍是成员。创建者离开项目后，其他合法成员可以领到 token，却可能打开 404。
- **边界：**token 本身按合同是短期 bearer capability。领取者被移除后在有效期内使用 token，不能单独据此认定已确认越权漏洞；本项记录授权语义和可用性问题。
- **完成标准：**统一签发与验证所依赖的授权主体或项目授权版本，明确有效期与撤销语义，补“领取者不等于创建者”的测试。
- **证据：** `delivery-probes.json`。

### 真实 HTTP 联调为何没有通过

现行脚本重建空库后就等待 API ready，没有初始化知识、配置知识 capability、提供 TEI/reranker 测试服务；还在 `scripts/workbench-postgres-http-e2e.mjs:842` 断言生成版本 `knowledgeReleaseId === null`，与当前强制知识合同不符。

需要重建这条测试的知识前置条件和成功断言；增加超时或跳过 readiness 都不能补齐覆盖。测试的 provider 本身是受控替身，因此即使修好该脚本，仍须另做真实模型与公网交付验收。

## 7. 按最小业务闭环推进

| 顺序 | 工作包 | 完成标准 |
| --- | --- | --- |
| 1 | 首次初始化、依赖风险与集成测试 | 空库可完成初始化；关键依赖风险有升级/隔离结果；带知识的 HTTP 联调可重复运行 |
| 2 | 输入与双产物生成 | 默认或明确选择“文档＋原型”；中文输入法安全发送；用户能看懂当前阶段、失败和重试 |
| 3 | 文档与知识闭环 | 切换不丢草稿；保存、预览、下载版本一致；定稿知识保留业务语义；项目可显式更新知识基线 |
| 4 | 交付可靠性 | 原型分享在无登录窗口可用，撤销/过期行为明确；坏导出不影响其他记录；真实 Word/PDF 打开可读 |
| 5 | 真实业务验收 | 同一项目完成下面这条路径，记录真实配置与产物版本，不能只贴模拟截图 |

真实业务验收路径：

1. 新用户开通账号并进入项目，确认知识已可用。
2. 输入一条真实中文需求，一次得到需求文档和对应原型，能查看知识来源。
3. 修改文档、切换产物、刷新，再预览并下载，确认内容没有丢失或版本错位。
4. 用匿名浏览器打开分享链接，检查页面跳转、交互、图片、过期和撤销。
5. 定稿入库后再次生成，确认使用完整的业务语义；更新知识后明确采用新项目知识版本。

控制体量：1.0.0 先围绕以上闭环优化。Figma、MCP、外部托管投递、复杂 Canvas Agent 扩展和额外导入源可作为独立扩展维护。当前 `workbench-project-route.tsx` 约 4,308 行、`run-processor.ts` 约 4,215 行；应围绕草稿、提交、知识证据和发布职责逐步拆分，保持合同和测试稳定，避免一次重写整套系统。
