## 功能说明

用户在线输入需求后，系统从本地 `knowledge-vault/`、项目数据库知识库和本地 `storage/` 检索授权知识，生成需求文档与原型。需求文档支持在线预览、编辑、发布、Word/PDF 下载；原型支持固定版本在线预览、分享和撤销分享。定稿版本可以写入项目知识库，后续生成继续引用已发布知识。

当前版本保留服务端项目权限、固定版本发布、分享 token 撤销、导出任务幂等、文档草稿保存、原型交互状态、知识引用证据和导出失败隔离。知识资产、测试、数据库迁移和协议版本均保留。

## 本次修复

本次修复针对线上发布候选的 PDF 导出段错误：`workbench-export-worker` 原来使用 Alpine Node 基础镜像，LibreOffice 转换 PDF 时退出码为 139。现已让 export-worker 的构建参数绑定到已固定摘要的 Debian Node 镜像输入；其他 Workbench 服务继续使用通用 Alpine Node 输入。CI、项目所有者发布流程和 Compose 的绑定已同步，避免构建环境不一致。

发布复核发现，构建阶段在 ARM64 runner 上用 AMD64 模拟执行 LibreOffice PDF 转换仍可能退出码 139。已移除构建阶段的渲染执行，把同一 DOCX/PDF 检查移动到部署器：部署器只对已验签的 `export-worker` 固定摘要镜像执行隔离的 `linux/amd64` 容器检查，容器无网络、只读根文件系统、限制 CPU/内存/PID，并在数据库备份和任何服务停止前完成。这样构建不会因模拟器中的 GUI/字体运行时崩溃误阻塞镜像产出，生产切换仍以真实目标架构的渲染检查为门槛。

真实栈浏览器验收发现生成背景在减弱动效下仍有透明度渐变。修复让系统减弱动效样式直接采用当前背景的目标透明度，覆盖动效库的内联与 WAAPI 动画，普通动效保持原有行为。使用真实组件与项目样式的浏览器测试先复现相同错误，再验证 PRD/原型首次显示、生成/完善阶段切换及系统偏好切换；没有放宽逐帧静止断言。

同提交完整 CI 复核时发现 `scripts/prepare-node-image.test.mjs` 仍断言旧的“构建阶段执行 LibreOffice 检查”行为。该断言与当前部署前真实 `linux/amd64` 隔离预检设计冲突，已改为验证检查器和模板仍进入运行时镜像，并明确要求由部署预检执行，不在 ARM64 模拟构建阶段运行。

登录页背景原先依赖外部图片服务，真实浏览器复核遇到首次加载超时及额外外部图片请求。两张原有背景图已作为应用静态 WebP 资源交付，外观保持不变；删除外部图片白名单，浏览器验收要求两张图片由本站成功返回，并拒绝任何非应用/预览来源的 HTTP 请求。

GitHub Actions 附件存储额度耗尽后，已清理 479 份废弃提交附件（263,589,106 字节），保留在用线上版本的回滚证据。当前技术浏览器检查及项目所有者发布链改为专用构建机持久证据目录 `/var/lib/workbench-ci-artifacts`：目录仅 runner 用户可读写，位于 checkout 和临时任务目录之外；每份证据绑定仓库、完整提交、run ID、attempt，逐文件记录并校验 SHA-256，原子写入，拒绝缺失、覆盖、合并冲突及符号链接。中间证据保留 1 天、最终签名包保留 7 天，上传新证据时清理其他 attempt 已过期的本项目证据。签名镜像、SBOM、漏洞扫描、来源证明和生产部署校验继续执行。
