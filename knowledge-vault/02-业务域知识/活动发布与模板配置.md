# 活动发布与模板配置

## 活动创建

活动创建的通用步骤是：

1. 进入“极速活动发布 -> 新建活动”；
2. 按业务选择活动类型和模板；
3. 配置页面、活动信息、规则、分享、奖品、表单或楼层；
4. 保存并预览；
5. 填写活动方案和前置审批信息；
6. 提交同级审核；
7. 审核通过后发布。

原始用户手册明确的活动类型包括资费订购、海报、问卷、抽奖、商机预约、聚合和答题；具体模板会随业务和区域扩展。

## 活动信息

| 配置区 | 字段 |
| --- | --- |
| 基础信息 | 是否测试活动、活动名称、活动标题、业务类型、活动集 |
| 时间 | 活动开始时间、截止时间 |
| 范围 | 适用集团/省份/地市、用户范围、登录方式 |
| 参与 | 总次数、按天/周/月次数、白名单、目标用户 |
| 渠道 | 加载渠道、活动编码、发展人编码、运营位编码 |
| 内容 | 活动规则、分享文案、活动方案、证明文件 |

活动名称在多份配置手册中要求不超过 15 字；实施时应以具体模板校验规则为准。

## 页面配置

常见页面资产包括：

- Banner、背景图、背景颜色；
- 分享海报和悬浮按钮；
- 抽奖区、权益区、礼包区、活动规则区；
- 标题、按钮、奖品背景和轮播区域；
- 广告位图片及跳转链接；
- 门店、打卡、记录、九宫格和抽奖按钮。

图片通常支持本地上传或从素材库选择；未配置时使用模板默认资源，清除默认资源后部分区块可以为空，但参与按钮、打卡按钮、抽奖按钮等关键操作入口必须保留。

## 审核与发布

- 预览链接用于发布前验证，可配合白名单访问。
- 长链接、短链接和二维码在正式发布后作为活动传播入口。
- 提交审核需要填写相应信息，并上传活动方案或前置审批证明文件。
- 审核通过后必须执行“发布”，状态才变为“已上架”。
- 已上架活动可以下架；下架支持立即下架或预约下架。
- 已下架活动可以重新上架，重新上架进入活动编辑页面。
- 活动可以复制，复制成功后生成新的可编辑活动。

## PRD 与原型重点

- 活动类型和模板的选择结果；
- 三步或多步配置导航的当前步骤；
- 页面默认素材、清除默认素材和必填操作按钮；
- 预览、白名单、二维码和正式链接的差异；
- 审核中、审核通过、已上架、已下架和拒绝状态；
- 每个状态下用户可执行的动作。

## 本机资料补充的版本边界

活动规则的“默认是否收起”与“查看更多默认展开”是两个极性相反的开关名称；前者开、后者关都可能表示前台收起。收起时显示前 N 行并允许查看更多后再收起；展开时全文显示且无收起按钮。N 的值没有明确，不能将两种配置名当作同一个布尔字段迁移。逐稿依据见 [[02-业务域知识/本机资料审读分册一|活动配置来源审读]]。

广西养成原型同时保留初版、调整版及废弃草稿，包含长图/切图、页签、悬浮入口、事件组、经验及奖券等设计；上海城市、河北省份和示例人员是组件数据，不能推导区域权限。部分“属性/样式配置”按钮实际只选中自身，不能据入口文案认定已经保存配置。该批逐页证据见 [广西与日志归纳](<storage/source-assets/cehuabao-local/review/prototype-interaction-guangxi-logs-topic-notes.md>)。

抽奖重构原型的页面配置注释要求剩余机会和参与人数默认关闭；参与人数的基础值为正整数，空值按 0，此后每次点击抽奖按钮加 1。这是点击累加的设计口径，不能写成去重 UV 或中奖人数。原版组件菜单为 6 项，另一版为 8 项；后者没有原版的 8 条配置注释，不自动继承。抽奖与悬浮按钮默认开启且不可删除、其他组件的默认开关、悬浮位置及 OAO 背景适用条件均须按对应页面版本取值。抽奖类型下拉有多种文案，实际关联面板仅有两个状态，不证明其余类型已实现。[逐页事实与版本差异](<storage/source-assets/cehuabao-local/review/prototype-interaction-draw-remainder-topic-notes.md>) 保留注释与 AST 的差别。

“模版命名管理”原型说明模板 ID 固定唯一，改名不影响已有用户数据、中奖记录和统计；表格与输入框的示例编码前缀不同，不能据此拟定编码合同。HTML 中 ID 输入禁用，取消按钮初始禁用，确定修改没有保存事件；表格详情跳转却指向导入审核页，应记为来源配置冲突。不能将命名说明当成保存或历史数据保护已实现的证据。来源为 [模板规范独立台账](<storage/source-assets/cehuabao-local/prototype-archives/prototype-interaction-ledger-template-naming.json>)，批量审核与导入规则归入 [[02-业务域知识/权限审核与运营治理|现有权限审核主题]]。
