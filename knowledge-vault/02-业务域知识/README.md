## 统一拆解模板

每个业务域都按以下结构维护：

- 业务定位：这个业务解决什么问题。
- 核心对象：涉及活动、素材、奖品、渠道、报表、审核或 AI 任务中的哪些对象。
- 主流程：用户端、后台端、审核端、数据端怎么走。
- 字段与配置：关键字段、默认值、校验、历史兼容。
- 状态与异常：正常态、空态、失败态、无权限、审核驳回、发布失败。
- 数据与报表：指标、筛选、导出、审计、延迟和脱敏。
- 风险与验收：资损、安全、权限、回滚、测试重点。
- PRD 重点：写产品文档时必须覆盖什么。
- 原型重点：生成原型时必须画什么。

## 组合规则

- 活动发布 + 奖品券：必须补库存、资格、核销、对账和资损。
- 签到/打卡 + 积分：必须补自然日幂等、次数上限、积分账本、发放补偿和统计口径。
- 活动发布 + 素材库：必须补引用影响、素材下线和历史活动兼容。
- 活动发布 + 报表：必须补活动编码、渠道编码、运营位和统计口径。
- AI 助手 + 素材库：必须补来源案例、素材选择、生成边界和人工确认。
- OAO/号卡 + 报表：必须补商机、订单、门店、发展人和渠道归因。
- 权限审核是横切能力，涉及导出、发布、素材、奖品、外链时默认必选。
