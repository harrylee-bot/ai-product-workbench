# AI营销助手与案例库

## 输入

- 业务目标、活动类型和区域；
- 用户触达渠道；
- 活动模板、历史案例和素材专题；
- 文案、页面或海报生成意图；
- 奖品、渠道、门店和时间约束。

## 处理

1. 根据活动类型和业务目标检索相关案例。
2. 根据文字意图搜索或推荐素材。
3. 结合模板和素材生成页面、文案或活动方案草稿。
4. 把生成内容拆成可编辑字段。
5. 由业务人员确认、修改并提交审核。

## 边界

- AI 只能生成草稿，不能跳过人工确认、权限和审核。
- 不能凭空补写奖品库存、真实接口、生产链接或审批结果。
- 生成结果需要标记引用的案例、素材和待确认假设。
- 涉及敏感用户数据、真实账号或生产配置时必须停止自动生成。

## 助手需求的版本与执行边界

本机新增稿补充的是不同阶段的产品需求，不能合并为当前已上线能力。4 月稿为三栏辅助配置与五阶段流程，5 月稿为八步确认，6 月稿改为终端、长图、派单、发布四次确认；7 月 V1.16 讨论稿为活动时间与终端、长图授权、奖品授权、派单、审核发布五个里程碑。四种流程、20 个热区与 1—3 个热区的限制分别按版本使用。

V1.16 把候选配置校验与落库交给业务系统，Dify 只生成非敏感计划和补丁候选；字段白名单、组织权限、基础版本及确定性校验通过后才原子应用，失败回滚。低风险可回滚配置连续执行，素材、奖品、派单歧义及审核发布保留来源要求的人工门禁。普通追加指令按最多三条 FIFO 排队，暂停等即时控制不占队列。这些是该讨论稿约定，不是本工作台工具权限或实际执行结果。

该稿的主奖品与可选第二奖品、自由/固定/就近门店、门店文件预检、提交前确认与发布失败重试均须按同一活动配置版本核验；未完成或失效的旧验证不能沿用。其“审批通过自动发布”与原手册“通过后手动发布”属于版本差异，不能全局替换。内文仍有门店里程碑编号、第二奖品图文及日志范围冲突。
