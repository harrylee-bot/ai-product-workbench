# 号卡OAO与商机预约

## 业务目标

通过活动页面收集用户意向，把用户信息、门店、套餐、销售品、发展人和渠道绑定为可跟进的商机或订单。

## 配置对象

- 活动基础信息和加载渠道；
- 用户表单字段；
- 敏感信息收集协议；
- 门店、区域和客户经理；
- 号卡/互联网卡套餐和销售品；
- 奖品或发奖规则；
- 活动规则和页面预览样式；
- 发展人编码、运营位和渠道参数；
- 活动方案与省内审批材料。

## 主流程

1. 选择商机预约或互联网卡模板。
2. 配置活动基础信息、活动时间和活动集。
3. 配置表单信息和敏感信息收集协议。
4. 选择门店、套餐、销售品和奖品。
5. 配置规则、页面和渠道。
6. 预览并提交审核。
7. 审核通过后发布。
8. 接收商机或订单状态回传，继续跟进和发奖。

## 异常与边界

- 重复提交需要返回已有商机或明确提示，不能重复建单。
- 门店无匹配、套餐失效、销售品不可用和渠道参数非法需要独立提示。
- 接口超时、回传失败和发奖失败要保留处理中或待补偿状态。
- 用户填写敏感信息前必须看到并同意收集协议。
- 商机、订单和活动数据按组织区域隔离，报表只展示用户有权限的数据。

## 本地补充审读：订购与北京项目

`html/订购类原型+北京项目` 的未登录页、模块配置、活动配置信息、滚动事件、页面配置 5 页已完成业务属性、完整 AST 参数、目标绑定、注释、初始状态、HTML 表单属性与文字映射审读，并核对全局配置、站点地图、stylesheet 和 CSS。此处融合历史设计，保留既有商机主流程；原型配置不证明当前线上办理、发奖或同步已实现。

模块设计涵盖单业务、多业务选一、订购赠送物品、权益领取、限时秒杀、业务轮播、页签、自定义组件组；网龄赠礼按 1—3、3—5、5—10、10 年以上分栏。前置展示条件分白名单和定时，定时按月、周或天；开启后登录前使用前置海报，登录后按白名单或条件显示模块。源文要求多个图片白名单 ID 以英文分号分隔，但实际文字写“英文；”，需确认分隔符。权益支持自定义／全部领取、领取次数及按天／周／月／场／每满足条件的频次，这些是配置意图，未形成真实资格和次数校验。

OAO 部分包含隐私政策、特别说明、下单备注、表单名称／展示名称和门店信息；提示仅选择 OAO 奖品时上传门店。页面允许替换表单及提交按钮背景，未显示配置时使用默认。适用地域、用户本网／异网范围、登录方式、主副卡、高套资格、前置活动验证及任务参数应逐区域确认，不能据这些形状自动扩充所有模板。

自定义提示分提交表单、非目标用户、奖品失效、重复领取、无法办理、未满足前置条件；“无法办理”组件提示却复用了再次领取的触发说明，保留为差异。活动名称用于唯一标识，标题用于 H5 展示；测试开关、场次和活动集均有配置文本，尚无真实调度与统计实现。

交互的实际边界：新增组件确定只隐藏对话层并切换已有面板，没有新增或保存业务节点；抽奖下拉有 5 种文字选项，实际只循环大转盘／砸金蛋 2 个状态。部分 description 的“状态 1／2”与 stateNumber 或目标状态排序不同，已按完整参数和目标状态映射保存。部分 radio 跨组件共用 name=a1，另一些独立命名并可同时 checked；星号不代表 HTML 必填校验。事件配置支持名称等 maxlength=20，定位动作实际为生日福利目标的水平滚动，注释又要求 1.0 固定切图位置，均不能视为通用事件编排引擎。
