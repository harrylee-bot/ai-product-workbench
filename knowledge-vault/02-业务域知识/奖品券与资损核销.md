# 奖品券与资损核销

## 奖品对象

| 类型 | 配置重点 | 结果 |
| --- | --- | --- |
| 抽奖奖品 | 奖品名称、图片、概率、库存、中奖限制 | 中奖记录和发放状态 |
| 权益/礼包 | 权益标题、礼包背景、礼包按钮、领取条件 | 领取记录和核销状态 |
| 券化销售品 | 销售品、适用范围、库存和订单关联 | 券/订单/核销结果 |
| 流量包/话费类 | 发放渠道、资格、额度、回执 | 发放回执和失败补偿 |

独立奖品需要在奖品管理中维护；商机预约终端手册还要求省内先在销售品平台配置奖品，再在活动中选择。

## 抽奖配置

抽奖类模板通常包含：

- 抽奖区域背景、抽奖按钮、奖品背景；
- 奖品列表和奖品展示；
- 中奖概率、库存和奖项限制；
- 用户总次数或按周期次数；
- 目标用户和领取时间校验；
- 中奖后领取、发放和核销。

每次抽奖必须绑定用户、活动和参与事件，重复点击不能重复扣次数、重复中奖或重复发放。

## 资损控制

1. 先校验用户资格，再扣减次数或锁定库存。
2. 库存扣减、中奖记录和发放请求需要幂等。
3. 发放失败不能显示为完全成功，应保留失败原因和补偿状态。
4. 奖品、券和流量包需要记录应发、实发、失败、补偿和核销。
5. 报表中的奖品消耗必须可以回到活动、用户、渠道和订单/商机。

## 前台状态

至少表达：未登录、无资格、可参与、次数已用尽、中奖待领取、领取成功、库存不足、发放中、发放失败和补偿中。

## 外部奖品配额与券包来源增量

广西定期抽奖原型的注释要求按后台时间段收集抽奖码，公布结果至下轮开始后恢复轮播，范围结束后按奖品配置数量关联抽奖码；“开始时间＞活动时间、截止时间＜活动时间”缺少比较对象，不能自行补成有效区间算法。轮询中奖与同奖多次互斥、非目标用户安慰奖及仅 OAO 奖品上传门店是对应文字设计，不证明随机性、资格、库存或发奖接口已经实现。来源见 [广西原型逐项归纳](<storage/source-assets/cehuabao-local/review/prototype-interaction-guangxi-logs-topic-notes.md>)。

抽奖重构不同页面的“中奖规则”“更多规则”面板状态数、顺序和同名状态不同，需以该页目标面板实际状态解释，不能仅凭 description 统一为后台开关。切换奖池的注释要求提示、清空奖品并滚动；AST 有真实切态和滚动分支，也有空目标及缺参数动作，不能据此宣称后台已清空奖品。“高套办理资格”注释仅广东显示，概率合计 100%、目标奖项、轮询与同奖多次互斥等也只是对应版本的规则说明。权益奖品无需抽奖可领、活动结束但未下架仍可办理的提示必须保留适用范围，结束与下架不能合并。详见 [抽奖重构来源事实](<storage/source-assets/cehuabao-local/review/prototype-interaction-draw-remainder-topic-notes.md>)；资格、抽样、库存与结算仍需正式实现证据。

外部发奖平台的 V1.4 讨论稿要求区分本地配置奖品名与实际中奖名，按租户、活动、独立奖品隔离配额，可用数为总量减已发放减预占。外呼前记原请求并预占，明确成功结算，明确失败或未中释放；结果不明冻结原请求先查询，不换新请求号盲目补发。关闭或跳转领取弹窗不等于再发奖，历史结果读订单快照。

同号同日稿仍有平台活动 ID 可否复用、唯一约束、新增表、内部与外部状态、未中奖是否扣额度等矛盾；另一技术稿明确 HTTP 方法、字段类型、稳定奖品 ID、幂等期限和回调仍待正式合同。上述配额规则是拟建需求，不证明外部系统已提供同样保证。沃土盲盒 V1.1 只读外部奖项、概率与库存，且取消任务平台二次资格；不能套用允许本地维护奖池的旧二期方案。

通用卡包需求仅在成功领券且券级开关开启时显示“查看适用厅店”，默认关闭；主动点击才唤起，返回 H5 保留状态，不重复发券。定位失败可到卡包首页提示，唤起失败留当前页重试。技术截图只在券详情通过布尔开关跳固定路径，不能证明成功页、当前券定位、签名、防重与降级均实现。

线下券的最近店、号码归属地、任意店与领券所选店之间存在版本和图文冲突，核销绑定未裁决前不能混成统一规则。详细来源见 [[02-业务域知识/微信资料审读-签到抽奖与权益履约|权益履约审读]]、[[02-业务域知识/本机资料审读分册一|盲盒及奖品来源]] 与 [[02-业务域知识/历史对接合同与日志定位|历史订单与日志证据]]。
