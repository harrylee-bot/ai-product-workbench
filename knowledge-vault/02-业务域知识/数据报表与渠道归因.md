# 数据报表与渠道归因

## 渠道对象

| 对象 | 作用 |
| --- | --- |
| 活动编码 | 标识一场活动 |
| 渠道编码 | 标识投放或进入渠道 |
| 运营位编码 | 标识页面或投放位置 |
| 发展人编码 | 标识发展人或业务归属 |
| 企微二维码/短链 | 连接用户触达和加粉结果 |
| 活动链接参数 | 在长链接、短链或二维码中传递归因信息 |

发展人编码管理包括新增、查询、详情、修改和删除，同时管理审核状态和关联绑定状态。编码需要保证同一地市不重复，多区域配置不能冲突，提交后进入审核，审核通过后生效。

## 企微短链数据

原始配置手册中的加粉数据至少包含：

- 活动编码和活动名称；
- 活动类型；
- 二维码展示次数；
- 用户扫码/触达结果；
- 企微人员或发展人归属；
- 按活动、区域和渠道筛选。

短链和二维码的跳转目标、参数白名单、失效时间和失败提示需要在需求中明确。

## 报表设计

通用报表应提供：

- 活动、区域、时间、渠道、运营位、发展人和状态筛选；
- 访问人数、参与人数、成功率、中奖/领取、加粉、订单、商机和转化率；
- 明细中的脱敏用户标识、时间、活动编码、渠道参数和处理状态；
- 数据更新时间、口径说明和导出字段；
- 按用户权限限制区域和组织范围。

## 归因链路

`活动链接/二维码 -> 访问事件 -> 参与事件 -> 加粉/商机/订单 -> 发展人/运营位 -> 报表`

任何一个环节缺少稳定编码，报表只能统计总量，不能可靠地解释渠道效果。

## 本地补充审读：运营首页与 SOP 的统计边界

已完整读取的 `html/首页`、`html/首页数据` 和 `html/营销日历` 原型作为本主题的历史设计补充。首页文字按平台管理员全域、集团仅集团、省侧仅本省显示，默认今日；今日折线按 24 小时，昨日／今日／本周／本月／近三日／近七日与图表保持一致，只有昨日与今日显示同期比较。订单区分普通、高值、互联网卡，账号区分 4A／门零。AST 只证明公告、预览和日历图片显隐，没有实现权限、统计聚合或日期比较。

首页数据排布包含 AI 策划宝／素材库的登录次数和人数，以及 PC／手机合计方案。来源直接写两端人数相加，未定义跨端去重；应保留为历史口径差异，不能当作当前真实 UV。示例日期、人数与次数均不是本次运营数据。

SOP 提报设计包含省份、营销主题、活动信息、政策、业务分类、审核与发布状态、触达／领券／业务转化，以及目标用户／员工范围、推送形式和执行材料。字段出现不代表归因链路已打通；本地原型无事件落库、统计公式、审核执行或真实导出。与上述既有活动／渠道／运营位／发展人归因对象一并确认，避免将文字状态或样例数字导入正式报表。

## 本地补充审读：待评审埋点与用户行为明细

`原型转HTML/模版命名规范` 的 sitemap 将“埋点日志（待评审）”放在广西抽奖活动初版待评分组。完整读取该页及其静态筛选子页后，保留为本主题的历史设计证据；未将它升级为当前事件或报表合同。

分析主体为活动参与用户，筛选维度有活动编码、省份、主／副卡和成功／失败／异常结果；指标选项有总次数、用户数、人均次数、分享次数、停留时长。事件按活动全局、抽奖、订购和表单归组，文字涉及登录、浏览、参与成功／失败、抽奖结果、订购点击／提交／支付、兑换和商机预约。表格组件配置列为脱敏用户标识、操作时间、活动信息、省份、参与场景、行为类型和操作结果，用户详情展示当前活动内的操作轨迹。

原型没有定义用户去重键、人均分母、停留时长起止、分享归因或成功状态映射；示例时区为 UTC-03:00，与当前默认工作时区不能直接混用。“导出 Excel”、时间筛选和查询有文字，但 AST 只覆盖组件初始化、弹窗显隐及视图切换，且一处面板切换没有目标。没有采集、落库、聚合、导出或时区转换实现证据；例值与样例日期均不作为真实运营数据。后续形成可执行需求时，应在已有活动／渠道／运营位／发展人归因对象之下明确这些口径和权限。
