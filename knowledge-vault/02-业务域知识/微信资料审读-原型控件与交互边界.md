# 原型控件与交互边界

> 本页仅供查验来源与实现边界，不另立规则入口。权限/发展人相关补充已归入 [[02-业务域知识/权限审核与运营治理]]，其余结论沿用各既有业务主题；保留本页作本地审读证据，新增内容尚未发布。

本页将页面文案和实际交互参数分开使用。第一批 8 页的全部解码属性、样式值、初始状态、注释、完整交互 AST、HTML 表单属性已读；包含 675 个控件及面板状态节点、20 个交互拥有者、23 个动作。全部非空对象引用和 2 个同项目页面跳转目标闭合，另有 7 个动作目标数组原本为空。空目标不能补写成已完成的业务操作。

完整控件树和样式通过 UUID 双向映射、精确样式字典及可逆增量保存，逐项重建与原 JSON 相等。读取范围包含全部值，没有用标签或交互 description 替代参数。原始图片像素、空间版式和浏览器实际运行未在本批完成，`originalReadComplete` 与 `pixelVisualReadComplete` 保持 `false`。这批原型提供需求线索，不证明线上接口、持久化、权限或事务已实现。

## 一人一码与加载渠道报表

一人一码数据报表主表为 16 列、表头加 10 行示例，字段包括素材 ID、脱敏用户手机号、店员、省市、活动编码/名称、类型、订购时间、订单号/状态、Y 编码、门店区域/编码/名称。实际有 7 个 text input，含活动名、渠道提示、素材 ID、活动编码、手机号和门店区域；“请选择”是输入初值，并非有候选项的下拉框。

查询、重置和导出控件没有事件。6 个输入控件的文字变化动作是隐藏自身；一个输入点击只切换另一图形的选中状态，后续显示/隐藏目标为空；一个表格单元格点击的目标同样为空。不能据此声称查询、导出、日期选择或报表口径已实现。样例状态包含成功和失败，未给出状态映射接口及数据更新时间。

加载渠道两页各 51 个控件。汇总页包含活动、省市、时间、活动集等条件及“是否加载渠道”；该条件实际有“全部/是/否”选项，其余部分下拉框没有选项。明细页表格有开始/结束时间、活动 ID/名称、加载渠道名称、PV、UV、订购数、省市与活动集 ID/名称。两页唯一交互是当前窗口相互跳转，并带 `includeVariables:true`，目标页面均存在。筛选、查询和导出未形成业务动作。

这些字段补充 [[02-业务域知识/数据报表与渠道归因]] 的展示范围。PV/UV、订单、活动集和渠道归因的分母、去重键、时间窗口、状态及权限仍需由对应需求和接口合同确定。

## 发展人编码与区域配置

“发展人编码”页只有 14 个控件，无交互。唯一加载渠道下拉框仅含“请选择加载渠道”；运营位/发展人等输入外观由图形表达，保存、取消、加号和关闭没有事件。样式中的 disabled 状态也不等于 HTML 控件存在 `disabled` 属性。

“内蒙发展人”页 75 个控件无交互。13 个 select 中，省份选项为内蒙；4 组地市下拉含呼和浩特等 8 市，另 2 组只有其余 7 市；另有一个发展人分类选项。所有下拉均未写 `required`、`disabled` 或显式 `selected`。草稿中、审核中、审核通过、线上及已关联/未关联等是展示文案，增删、确认和取消没有事件。地市选项差异须保留为待核对差异，不能推导成接口权限或行政区域完整清单。

这两页补充 [[02-业务域知识/权限审核与运营治理]] 与 [[02-业务域知识/数据报表与渠道归因]]，不能替代已有发展人配置手册中的审核、区域不冲突、绑定和删除限制。

## OAO 与四川奖品配置

北京 OAO 页有 32 个控件/状态节点。一个动态面板有展开/收起两态，点击动作将自身切换到下一个状态并循环；`showWhenSet:false`，没有业务条件。姓名、手机号、厅店和终端信息是 4 个真实 text input，提示写入 `value`，未见必填或格式验证。上传/导入、终端信息筛选、预约提交没有动作，无法据此证明导入和预约流程。

四川原型有 40 个控件/状态节点，包含奖品名称、类型、展示名称、offerId、受理号码类型、是否 FTTR、融合新装/存量加装等配置线索。2 个展开/收起面板仅切换自身状态。另两个按钮分别有 1 个和 2 个 `setPanelState`，但 3 个 `panelsToStates` 都为空。主卡、副卡、不限制三个 radio 各用不同 `name`，HTML 没有表达同组互斥，也没有初始选中或业务校验动作。offerId 输入提示多个值用英文逗号分开，未提供解析、去重及非法输入处理。

因此号码资格、FTTR/融合判断、权益适用条件和 OAO 回执仍按具体模板需求与对接协议确认，不能将动态面板的开合当作条件判断或发奖执行。相关文档冲突见 [[02-业务域知识/微信资料审读-签到抽奖与权益履约]]。

## 奖品运营与库存日志

奖品运营页 188 个控件，无动态面板。主表为 11 列、表头加 10 行示例，字段为序号、奖品编号/类型/名称/图片、总库存、消耗库存、剩余库存、创建人、最后保存时间和库存变动日志。库存日志另为 8 列、表头加 2 行，字段为操作时间、类型、操作人、变动数量、操作前后库存及备注。示例为“发放成功”扣减 1：100→99，以及“编辑增加库存”增加 100：99→199；这是示例账目，不能认定为库存事务已经执行。

日志所在 layer 初始 `visible:true`，不是由“查看”打开的隐藏弹窗；所有“查看”和关闭 x 没有事件。查询、重置、导出也没有事件。实际 4 个 text input 中，“奖品类型”的“请选择”不是 select；奖品名称输入框却使用“请输入活动编码”初值，保留为标签与输入提示冲突。3 个文字变化动作只隐藏输入自身，另一个点击切换选中状态后显示/隐藏目标为空，奖品图片单元格点击的目标也为空。

该页为 [[02-业务域知识/奖品券与资损核销]] 补充了库存明细及日志展示字段；没有证明库存锁定、扣减幂等、发放回执、失败回补、权限和导出能力。
