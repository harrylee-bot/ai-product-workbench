# AI 销服与省份原型交互

本批完整读取 11 页的全部控件业务属性、初始显隐和选中状态、HTML 表单属性、控件文字映射、页面注释及完整交互 AST 参数。包含 2,641 个控件及面板状态节点、172 个交互拥有者、410 个动作；379 处非空对象、面板及表达式目标引用均闭合，面板状态索引有效。同时保留 80 个空目标动作、5 个缺失目的地的页面跳转，不将其写成可用操作。相似页面也逐页重读。

[逐页审读台账](<storage/source-assets/cehuabao-local/prototype-archives/prototype-interaction-ledger-regional.json>) 记录源 SHA、读取文件与完整字符范围、AST 哈希、初始状态清单、逐页规则和异常；[可逆投影清单](<storage/source-assets/cehuabao-local/prototype-archives/interaction-regional/manifest.json>) 对应完整原始树、HTML 控件和图片路径。可逆树与全部 2,120 份页内独立样式字典已经机器重建、精确相等及哈希校验。样式坐标未逐项人工审读，图片像素、空间版式和浏览器运行未完成；图片状态路径的读取不等于读取图片内容。两份唯一 HTML 内联初始化脚本已读并以精确 SHA 映射复用，未执行归档 JS、加载外部组件或联网。

七个项目的 configuration、sitemap、additionalJs、additionalCss、globalVariables、默认及自定义 stylesheet 也已逐份全文读取，六份唯一全局 CSS 全文读取；仅 APP 室与广西的完全相同 CSS 在逐字节及 SHA 核验后复用。站点地图与本批 11 页对应；全局变量都只有空字符串 `onloadvariable`，没有定义登录态或业务计数。附加脚本／样式是调试、站点地图、页面注释与提示管理器的引用列表，引用名称已读不代表引用源码已在本记录读完。CSS 统一移除了原生 outline，键盘焦点表现尚未运行验证。[全局上下文审读证据](<storage/source-assets/cehuabao-local/prototype-archives/interaction-regional/context-read-ledger.json>) 保留逐项目完整范围。

本页是历史来源的本地知识草稿。静态配置样例、原型文字、UI 状态切换分别记录，不提升为现行业务基线或线上实现证据。与 [[02-业务域知识/微信资料审读-原型控件与交互边界]]、[[02-业务域知识/微信资料审读-抽奖重构与模板命名原型]] 和 [[02-业务域知识/微信资料审读-结构化数据与测试依据]] 配合使用。

## AI 销服：整合、美食、骑马

整合页覆盖活动名称、标题、时间、地区、本网／异网用户范围、SSO／免密／短信登录、异常话术、机器人话术、抽奖及发奖两组奖品、次数及周期、每日库存和发奖时机。基础配置初始可见，页面、两楼层、悬浮层初始隐藏；配置入口和返回按钮控制显隐。异常开关打开异常配置，发奖确认开关切换两组配置，机器人开关打开对应话术。测试、每日库存等开关只循环自身状态。发奖时机包含生成、下载、分享后发奖，但未见 AI、生图、打卡、抽奖或发奖请求。两个关联奖品跳转缺少目的地。

美食页完整需求文字明确：最多选择 9 道菜，超限提示；生成后展示优惠券；分享发奖需要确认；发奖记录首次确认后不再自动展示，可从参与记录查看；发奖与前置跳转同时存在时先发奖再跳转。页面提供菜系、更多菜系和分享层的显隐，川菜、返回、更多和分享关闭动作可追踪至具体目标。轮询关闭时显示概率配置，开启时隐藏；发奖确认开关切换对应配置。上述限选、首次确认、记录查询和先发奖后跳转规则仍只是需求文字，没有完整业务调用；关联奖品跳转缺失目的地，两个下拉控件没有选项。

骑马页只有 13 个可见节点，无页面或控件事件，也无 HTML 表单控件。门店、拍照／骑马纪念照、去打卡、规则为静态文字或图片；未据此推断拍照、打卡或抽奖链路。关联主题为 [[02-业务域知识/AI营销助手与案例库]] 与 [[02-业务域知识/奖品券与资损核销]]。

## APP 室：切图与长图配置

第一页面包括切图／长图模式、每行 1／2／3 张图片、组件和图片添加、礼包、操作、标题图，以及 189.cn、第三方、APP 原生、无链接四类跳转。基础配置初始可见，页面与悬浮配置隐藏。模式切换和返回只有面板显隐，日期框只是切换选中状态并执行空动作，没有日期选择实现证据。

第二页面是单长图配置，逐页读取了独立 ID、字段和 AST，未按外观相同复用结论。“切换切图模式”只是文字，没有绑定事件。两页均有立即／自然月次月发奖、发奖用户清单、办理起止、发奖前提示等配置文字，未见真实上传、发奖或保存请求。

第一页面的发奖清单开关与异常开关都控制异常话术面板；第二页面也存在相同类型的错连，已按各页 ID 独立记录。禁用活动规则开关的两个分支均为空目标动作，不能证明禁用规则已生效。关联 [[02-业务域知识/活动发布与模板配置]]。

## 广西：邀请、抽奖、奖池与时间范围

广西普通页标注轮询与同奖多中互斥、开启后限定概率及库存类奖品、同手机号或同微信 ID 视为同一用户、老友为近 3 个月未登录公众号用户、新粉为未关注用户，以及挑战成功次数默认 1。实际两个开关各自循环状态，没有互相设置，互斥只存在于鼠标提示文字；用户资格、进度和剩余次数开关没有调用服务。抽奖次数和中奖次数的 1、天／周／场周期是此原型样例，不能成为所有活动的统一默认。异常开关有明确显隐目标，禁用规则与关联奖品是空动作。

广西抽奖主页面覆盖奖券连抽消耗、定期范围、公布时间、库存和每日库存、入网有效时间、概率、保底次数、目标用户、奖池、轮询、同奖多中，以及经验等级、签到／浏览／公众号充值／流量加仓等任务、经验和奖券奖励、三楼层、轮播、图片和海报。经验 100、奖券 3 等为样例。完整读取中继器 propMap、data、dataProps 及内嵌 JSON：提示按抽奖点击次数切换奖池，轮询与同奖多中互斥，同奖多中开启后业务奖品可设置办理次数。

四条页面注释均保留：抽奖开始／截止时间用于从后台收集指定区间编码；公布时间是中奖结果展示日，展示至下一轮开始后改为轮播；默认三个奖池分别配置奖品及概率，第二保底池可用两奖品表示 S／A；增加时间沿用范围规则。首条时间约束原文为“开始时间＞活动时间；截止时间<活动时间；”，含义不清，尚不能据此制定校验条件，需在当前需求确认边界。

主页面的多个 Axhub 初始化动作读取 `AxhubAntdJsLink`，缺省指向外部组件；本次只读取完整脚本内容，未执行或下载，不能推断组件运行结果。“展示奖券数量”开关实际控制异常话术面板，部分配置入口未统一隐藏第三楼层，存在叠层路径；奖池、轮询、同奖多中等多个动作的目标数组为空。关联奖品跳转缺失目的地。

广西抽奖第二页面是另一份长图配置，全部独立读取。它的发奖清单开关也连到异常话术层；禁用规则、关联奖品等为空目标动作，“切换切图模式”没有事件。关联 [[02-业务域知识/微信资料审读-抽奖重构与模板命名原型]]、[[02-业务域知识/微信资料审读-签到抽奖与权益履约]] 和 [[02-业务域知识/奖品券与资损核销]]。

## 深圳低升高：OAO 表单与权益

覆盖权益产品、竣工受理关联、门店信息、目标用户、二次确认、提交文案、话费立即／自然月次月发奖、协议、长图、海报、弹窗背景和按钮。基础配置可见，页面、悬浮、提交弹窗、文件与异常层初始隐藏。表单弹窗有显示和切换动作；文件开关打开“文件”层，但该层只有图片与上传文字，HTML 没有 `type=file`。最终用户表单有一部分位于未读像素图片中，未推断图片内姓名、手机号或提交逻辑。

此页禁用活动规则确实有规则控件的隐藏／显示目标，区别于 APP 页的空动作。权益、受理关联等仍有空目标动作；“2 工作日联系”只是配置示例，未见时限任务或真实收单处理。关联 [[02-业务域知识/号卡OAO与商机预约]]。

## 湖南裂变：发起、助力与自然月权益

基础配置可见，页面、悬浮、助力信息、分享与海报隐藏。发起者和助力者奖品列表各自包含“有目标用户／无目标用户”两个状态，默认首态，但未见开关实际切换列表。配置包括双方奖品、二次确认、奖池、助力记录／人数／持续时长、发起及助力资格、大网／互联网卡／校园卡、截止时间样例 24、奖品有效期，以及分享前后文案与标题。

文字明确当月自然月有效、未兑换过期自动失效、查看详情改为“已过期”，但未见日期校验或发奖调用。异常话术初始可见，异常开关只循环自身状态，没有面板状态变化处理；禁用规则、关联奖品和删除等含 19 个空目标动作。背景色样例带空格 `# FFFFFF`，数值输入没有原生上下界约束，需在新需求中明确验证。关联 [[02-业务域知识/签到与任务积分活动]] 与 [[02-业务域知识/微信资料审读-签到抽奖与权益履约]]。

## 贵州签到：任务、经验与月度清零

基础配置可见，页面、两任务配置、悬浮、异常、话术层隐藏。两个任务开关分别控制对应预览楼层图片，异常和话术开关控制各自配置层。测试、每日库存和目标用户等开关只改变自身状态，未校验资格或库存；禁用规则两个分支、日期和删除等共 6 个空目标动作，添加奖品跳转缺失目的地。

业务文字涵盖日／周／月打卡次数、经验、成功与上限话术、不需要登录、二次确认、奖品库存和每日库存、目标用户来源、两项任务、经验阈值 100／200／300／400／500 与满值兑奖。单次经验 100、次数上限 5 为样例。日周期与月周期分别有一个初始选中单选框，它们使用不同 HTML name，不能据此推断属于同一互斥组。

页面明确“按自然月每月 1 日零点清零”，这是本来源可确认的需求文字；完整 AST 没有计数归零服务，尚缺清零对象、时区、历史记录保留与幂等的当前需求确认。关联 [[02-业务域知识/签到与任务积分活动]]。

## 继续编写需求时的证据边界

星号、字数计数、步进外观和默认值不等于输入校验；这些页面的相关 HTML 未提供 required、min、max、maxlength 等约束，多数 radio name 逐控件独立。后续文档应明确必填、格式、互斥、次数／库存、资格、奖励顺序、任务重试与验收，不由界面外观补写已实现结论。

完整 AST 可证明本地原型的显隐与状态路径。内部引用闭合不能证明页面跳转有目的地，状态开关也不能证明服务端处理成功。空动作、错连和外部组件尚未运行的部分均保留在逐页台账；最终像素、视觉版式、真实接口、持久化、权限、计数、发奖事务和线上版本不在本批完成范围。当前所有补充仅落本地，未发布或推送。
