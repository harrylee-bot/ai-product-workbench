# 权限审核与运营治理

## 菜单与数据

菜单权限决定用户可以进入哪些模块，组织区域决定用户可以看到哪些活动、素材、商机、订单和报表。页面不能只隐藏按钮，还要在接口和导出层复核数据范围。

## 审核治理

- 同级审批；
- 发起人不能审批自己；
- 审核详情可查看活动配置和证明材料；
- 审核拒绝需要原因；
- 审核通过后才能发布；
- 正式活动可下架和重新上架；
- 活动列表需要清楚展示当前状态和下一步操作。

## 白名单与测试

预览链接用于发布前验证，白名单控制可以访问预览的用户和有效时间。测试活动要与正式活动区分统计，不能把测试数据混入正式运营报表。

## 运营维护

活动维护至少包括列表筛选、详情、编辑、复制、预览、提交审核、发布、下架、预约下架、重新上架和删除。每项操作都应记录操作人、时间、对象、前后状态和失败原因。

## 素材与运营操作审核的版本补充

素材后台原型把“审核员、审核节点、菜单及需审核操作、审核类型、审核流程、我的申请、审批管理”分别配置。审核员页面有手机号输入、姓名禁用待带出、启用/停用，以及按节点选择审核员的设计；“导入审核员”仅为入口文案，没有文件输入或导入接口。审核类型详情的正式注释要求人员电话、姓名脱敏展示。节点 ID 自动生成只出现在输入提示中，不能据此认定已有编号生成规则。

存在三套须分别保留的审批设计：

| 来源与范围 | 原文规则或表现 | 本地归纳边界 |
| --- | --- | --- |
| 手机版操作指南及平台手册 | 同区域同级审核、本人不能审批自己；审核后下载/发布按业务对象区分 | 保留已有关联来源，不被新草图覆盖 |
| `手机策划宝后台20251119/审核员管理` 注释 | 为节约开发，1.0 仅终审、一级审核人；选择节点后，流程只列该节点审核员 | 与同页“初审/复审”样例并存，不认定多级已上线 |
| 新增审核流程及后台流程管理 | 一级只可加一个节点，多级可加节点；初/复/终审、审核员、优先级、全部/任一审核；另有同级/指定人审核 | 作为后续配置设计，未证明真实规则执行和保存 |
| PC 审核流及编辑审核 | 默认同级互审、省份审核、上级审核、指定人、同级互审后兜底 | 不外推为全平台统一链；指定人流程末尾却写上级审核人，保留冲突 |
| `模版命名规范/审核管理_批量` | 默认同级同角色同事审批，自定义按省/市/区县/厅店指定人 | 历史待评分组；批量删除、锁定和解除锁定仅为文案，不能认定后台操作已实现 |

流程管理另有注释要求同级审核员默认为全部，每个省份对相同菜单仅能创建一个流程。页面内优先级一处列 1–6，另一处列 1–10；“任一审核”在一个版本中是禁用字段，另一版本允许“全部/任一”选择。实际 HTML 的同级/指定人 radio 使用不同组且都预选，不能由 UI 外观推导互斥和校验已经生效。这些版本差异在确认适用版本前不合并成一个执行合同。

运营操作审核涵盖标签、审核员、专题、分类、日历、标签配置、广告位等菜单下的编辑、删除、禁用、上架或导入；不同菜单拥有不同操作项。页面显示流程选择并不等于授予操作权限，菜单、组织范围、素材可见范围和审核范围应分别复核。

## 申请状态与确认生效

草图区分待发和已发审核。待发列表写有发送/取消审核、选择多条和一键打包提交；已发列表展示审核中、已通过、当前节点、撤销、详情和流转记录；审核通过的申请还出现“确认修改”。审批管理展示待/已审批、通过/拒绝及“追回”，记录包含节点、审批人、操作、创建/完成时间、耗时和意见。须确认“通过”到“确认修改”的真实生效时点，以及撤销、追回和打包的允许状态，不能自行补成通过即自动修改或可任意撤回。

这些页面中真实事件主要是切换待/已审批面板、同级/指定配置面板和外部 Axhub 组件初始化。多组 checkbox 的 selectedChange 表达式为空块，送审、通过、拒绝、追回、导入、暂存等控件多无动作；未形成后台审批、授权或事务证据。原型中的空跳转、空目标及空表达式在逐页台账保留，不替作者补全。

## 区域可见与账号口径

素材和专题的省份范围按各自正式注释记录：默认全部展示且只含审核通过素材，未勾选的省份不可见；“全部/范围可见”和省份选择器外观不证明服务端隔离。编辑审核还画有省/市/区县/门店及兜底人；内蒙发展人原型下拉选项不一致，只作为待核对样例，既有手册中线上版本/草稿、绑定及审核中删除限制继续保留。

“策划宝未激活账号”页四条注释明确归属地区和创建时间默认全部，仅模糊检索账号或工号；完成登录后该条移出列表，实际账号统计使用另一接口。这是待登录/未激活列表口径，不能与活跃账号、实际账号数或使用次数合并。选择器内 3,632 行地区数据已经完整读取，但它是原型组件的历史数据，不是当前组织权限表或现行行政区划标准。

## 审核批量配置与导入记录

历史 `模版命名规范` 项目将审核配置的批量管理与导入文件分开展示。批量管理可按名称关键词和地区检索，默认审核与指定人审核沿用上表的来源边界。实际 AST 只有全选 checkbox 改变序号面板状态，再由状态事件切换上级面板；没有批量删除、锁定、解除锁定或后台审批动作。

导入列表区分文件、省份、导入时间、状态、创建人和详情，包含“完成但部分失败”的示例，不能将完成等同全部成功。详情明细另列省/市/区县/厅店、导入状态、是否生效和备注。原型没有给出失败重试、重复覆盖、部分成功事务或生效时点合同；详情页也没有筛选、分页和明细操作事件。

删除警告写明删除文件会删除文件内全部审核信息，应保留其设计意图及影响范围。该对话框初始可见，确定和关闭实际都只隐藏对话框，未删除任何数据。导入页写支持 XLS/XLSX、下载模板和拖拽上传，但没有文件输入或交互事件。以上均融合为现有审核主题的历史待确认来源，不能用于宣称批量审核和导入已上线。逐页依据见 [模板命名项目 17 页台账](<storage/source-assets/cehuabao-local/prototype-archives/prototype-interaction-ledger-template-naming.json>)及其 `审核管理_批量`、`导入审核`、`导入审核详情`、`导入页面` 来源笔记。

## 日志映射配置的角色与变更边界

运营日志原型把请求路径与业务中文名称单独配置。正式说明将新增、编辑、删除、导入限于开发角色；产品、运营等人员仅查看和使用搜索预览。该限制针对映射配置变更，不能据此外推所有日志明细的角色权限。

映射导入要求 CSV 不超过 2M，第一列技术请求路径、第二列业务中文名称。路径须与日志实际路径完全一致、区分大小写且不含 URL 参数；中文名用简洁业务术语，不含“接口”“API”“#”等技术词或特殊符号。可选状态为启用/禁用，注释要求启用后立即生效、禁用后暂不生效；备注仅供协作、不影响功能。删除提示明确删除后日志映射失效，因此应区分禁用和删除。批量导入实际校验、匹配前如何处理带查询参数的日志路径、重复路径处理及变更生效机制仍需服务合同确认。

本批真正交互只打开或关闭新增、导入、删除对话框，以及显示“保存配置成功”提示，没有保存、导入、删除或转换请求；导入框的确定/取消甚至指向隐藏“新增映射”面板，不能当成成功导入。完整规则与实际 AST 的差异保存在 [广西及运营日志 18 页台账](<storage/source-assets/cehuabao-local/review/prototype-interaction-ledger-guangxi-logs.json>)和[3 项目上下文](<storage/source-assets/cehuabao-local/prototype-archives/interaction-guangxi-logs/context-reading-ledger.json>)。日志业务字段继续关联 [[02-业务域知识/数据报表与渠道归因|数据报表与渠道归因]]、[[02-业务域知识/历史对接合同与日志定位|历史对接合同与日志定位]]，本节沿用本主题，仅本地待发布。
