# PRD 输出边界与交付规范

本文件专门约束 PRD 的“写作边界”，避免把开发执行细节或运维材料硬塞进 PRD。

## 一、PRD 必须包含

- 业务目标与验收口径
- 页面与后台字段映射（不必含具体 SQL/接口签名）
- 状态链闭环（草稿/预览/审核/发布/下线/回滚）
- 风险与异常态
- 权限与日志要求
- 数据口径与报表筛选策略
- 所引用规则：`[[02-规则约束/需求文档沉淀/需求文档通用约束|需求文档通用约束]]`、`[[02-规则约束/需求文档沉淀/营销活动与资损约束|营销活动与资损约束]]`

## 二、PRD 明确禁止包含

- 资损明细表（开发执行表）
- 代码级实现细节（SQL、接口签名、部署参数）
- 具体测试脚本（放测试用例/任务清单）
- 第三方密钥、真实凭证、生产环境账号、内网路径
- 运行期配置清单（留给开发补充）

> 约束：**资损表不在 PRD 里生成**。
> 该内容按“开发执行面”单独维护，由开发补齐对接项、核对结果与验收清单。

## 三、PRD 与原型分工

- PRD 负责说明“要做什么、为什么、验收标准、边界和风险”；
- 原型负责说明“怎么呈现、怎么配置、怎么审核和发布”；
- 开发补充负责“怎么落地、哪些接口、资损表如何归档”。

## 四、输出格式建议

- 使用统一章节序：
  1. 业务背景与目标
  2. 业务对象与用户路径
  3. 页面/后台字段清单
  4. 异常与边界条件
  5. 审核与发布
  6. 验收标准
  7. 待确认与假设
- 每个章节都保留`知识来源`，便于知识检索回溯。

## 五、与知识检索的约定

- PRD 里每条关键决策都要挂回规则/案例/模式：
  - 架构与逻辑：`01-产品知识`
  - 约束与风险：`02-规则约束`
  - 页面/状态映射：`04-原型模式`
  - 同类经验：`03-案例库`

## 六、交付闭环

1. PRD 输出 `待确认项` 不能空。
2. 风险项必须给出缓解动作。
3. 需要 `开发补充` 的项单独标注“待开发填写”。
4. 在确认门流程中保持 `已确认` 前不进入代码实现。
