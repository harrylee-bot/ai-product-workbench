# 历史业务增量规则

历史业务增量不是重新设计产品，而是在已有对象、流程、页面和状态基础上做增量。

## 识别信号

- 用户说“优化、增加、新增、补充、调整、支持某省、增加字段、增加开关、增加筛选项”。
- 需求提到已有活动、模板、素材、奖品、报表、页面或原型。
- 需求只改变某个环节，但可能影响历史数据或已发布内容。

## 必须继承

- 原有角色和权限范围。
- 原有对象：活动、素材、奖品、渠道、报表、审核任务。
- 原有入口和页面路径。
- 原有状态流转：草稿、预览、审核、发布、下线、回滚。
- 原有报表口径和历史数据展示方式。

## 必须补充

| 增量类型 | 必须补充 |
| --- | --- |
| 新字段 | 字段归属对象、默认值、校验、历史数据、报表口径。 |
| 新开关 | 默认开关状态、生效范围、开启/关闭影响、灰度和回滚。 |
| 新筛选 | 数据来源、权限范围、默认值、空态、导出是否同步。 |
| 新状态 | 状态含义、触发条件、可执行动作、异常回退。 |
| 新页面区块 | 入口、可见角色、前后台联动、数据加载和失败态。 |
| 新报表字段 | 计算口径、时间口径、导出口径、脱敏和历史补数。 |

## 输出模板

```text
继承：沿用哪个历史业务、对象、页面、流程。
新增：新增字段/开关/筛选/状态/报表/权限。
影响：草稿、待审核、已发布、已下线、历史数据是否受影响。
兼容：默认值、空值、旧数据、旧活动复制如何处理。
验收：新增路径和历史主路径都要回归。
```
