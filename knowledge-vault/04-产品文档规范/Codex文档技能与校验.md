# Codex文档技能与校验

## 两类技能的职责

| 技能 | 本次整理后的用途 | 编写依据 |
| --- | --- | --- |
| `requirement-doc-template` | 中文需求说明书的章节、业务描述、渠道表、降级、安全基线和内容检查 | 本机 Codex 同名技能的当前文件；项目副本为 `integrations/deerflow/skills/requirement-doc-template/` |
| `documents` | Word 文件的读取、模板处理、创建、编辑、修订、批注、渲染和页面检查 | 本机 Codex runtime 的 `26.1025.11240` 技能包；原始技能快照保存在本地来源归档 |

用户的本次交付要求优先。采用需求模板时，以该模板及明确要求控制版式，通用文档技能负责操作与检查；不能用通用设计预设覆盖指定模板。技能包中针对云端文档的操作说明不构成向外部目的地上传的授权。

历史策划宝原型中的“文档中心”是产品业务模块，其同级互审、上架、下载和版本还原规则只作对应需求来源。它们不是 Codex 编写 Word 的技能步骤，不能据此给本机文档操作增加审批、联网或上传流程。

## 当前需求编写规则

- 保留 H5 示例主章；从 `2.2` 起按实际功能命名，不固定三个通用业务小节。
- 分别按业务需要选择流程图和架构图，不强制两张同时出现，不为无关功能扩写总体架构。
- 黑色文字、白色表格背景、黑色边框；修正模板网格、空白和跨页问题。
- 一张渠道表、具体可验收内容、适用的降级方案和 21 项安全基线继续保留。
- 接口影响说明仅使用有依据的信息；不为补章节虚构接口。
- 交付前移除模板提示及占位文字。最终文档不使用模板专用的占位放行参数。

## 文件与验证入口

| 文件 | 用途 |
| --- | --- |
| `SKILL.md` | 任务范围与编写流程 |
| `references/structure.md` | 主章、实际功能节、图示选择、渠道及安全基线 |
| `references/quality-standards.md` | 内容质量、样式、命名与验收要求 |
| `assets/requirement-template.docx` | H5 示例样式及表格结构 |
| `scripts/docx_quality_check.py` | 检查正文、表格、章节、渠道、安全基线及黑白样式 |
| `agents/openai.yaml` | 技能名称和使用提示 |

本机文档操作使用 Codex 工作区依赖加载器提供的运行时和库。首次创建或编辑 DOCX 前先按 `documents` 技能执行一次 `mark_artifact_operation_started.mjs`，生成或修改完成后必须运行 `render_docx.py`，打开每页 PNG 做逐页视觉检查，再根据结果迭代。需求检查器执行后，还需要关注跨页表格、图片、缺字、遮挡和异常空白；渲染失败应记录实际原因，不能把结构检查通过写成视觉验收通过。渲染产物只作本地 QA，不作为知识库正文或线上发布输入。

本轮复核时，实际安装的 `documents` 包已更新到 `26.1025.11240`。当前快照的 80 个文件已与安装目录逐文件对齐，摘要见 `storage/source-assets/cehuabao-local/skills/documents-snapshot-manifest.json`；先前 `26.1020.11618` 快照作为历史来源保留。当前包要求通过依赖加载器选择运行时，文档渲染只使用其提供的打包 LibreOffice；不把用户桌面的另一个 Office 安装当作同一条校验链。新建或编辑 Word 时遵守技能的操作标记与逐页渲染流程，纯读取和归档不运行创作标记。

## 与现有应用的边界

本地新增的 `workbench.prd.v3` 已将业务章节改为从 `2.2` 连续编号的实际功能小节，验收可嵌入对应功能，流程图和架构图分别可选。Runtime 生成与引用校验、Canvas 展示和编辑、版本保存、HTML/Word 导出及定稿知识解析已一并适配，仍沿用原有应用与知识链路。生成尚未定稿时的 Canvas 预览也递归展示渠道选择、安全基线、假设和引用等语义字段，避免只显示正文块而漏掉影响评审的业务约束。旧 v1/v2 产物继续按原协议读取和修改，不将历史版本强制改写成 v3。

新建文档仍须保留完整渠道、降级、安全基线和来源关系；自由编排不表示可以省略已明确要求的内容。节内图由结构化数据安全展示，编辑正文时保留原图及业务标识。本地回归、构建及导出逐页视觉检查已完成，当前未部署线上，不能据此宣称在线生成已采用新结构。

本次资料及技能整理只形成本地候选；应用版本继续为 `1.0.0`，发布由用户后续明确指令触发。来源与逐份审读入口见 [[07-来源资产索引/本机资料完整审读索引|本机资料完整审读索引]]。
