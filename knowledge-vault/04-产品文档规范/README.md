# 产品文档规范

本目录回答“产品文档怎么写”。AI 写 PRD 或需求说明书时，必须从产品架构和业务域知识出发，并按需求说明书模板输出可评审、可验收、可转测试用例的正文，而不是把用户口述扩写成自由长文。

## 写作原则

- 先说明业务目标，再说明产品对象。
- 先说明主流程，再说明字段和状态。
- 前台、后台、审核、报表、权限、风险不能拆散。
- 历史业务必须写“继承什么、变化什么、影响什么、如何兼容”。
- 新产品必须写“接入哪个能力层、复用哪些能力、新增哪些对象”。

## PRD 必备结构

默认使用需求说明书模板结构：

```text
封面
版 本 历 史
目 录
1 引言
1.1 项目背景
1.2 文档范围
1.3 使用场景（必填）
2 业务需求
2.1 页面链接
2.2 核心业务规则/功能说明
2.3 核心流程/状态/页面要求
2.4 验收标准
3 业务降级方案（必填）
4 需求安全基线要求（必填）
```

在线 PRD 画布可以不渲染封面分页和 Word 页眉页脚，但正文结构必须保留 `1 引言`、`2 业务需求`、`3 业务降级方案（必填）`、`4 需求安全基线要求（必填）`。
