# 按业务域写作规则

按 [[04-产品文档规范/PRD标准结构|当前 PRD 标准结构]] 从 `2.2` 起以实际功能命名。下表是对应能力已在本次范围内时的检查维度，不要求为了凑齐文档而扩展业务。

| 业务域 | 涉及时核对 |
| --- | --- |
| 活动发布 | 模板、页面配置、规则、预览、审核、发布、下架 |
| 素材库 | 上传、专题、标签、审核、水印、下载、引用影响 |
| 抽奖/奖品 | 概率、库存、资格、次数、发放、失败和补偿 |
| 企微/渠道 | 活动码、二维码、短链、发展人、运营位和归因 |
| 商机预约 | 表单、敏感信息协议、门店、套餐、销售品、回传 |
| 签到/打卡 | 业务日期、门店、次数、积分、奖励和重复请求 |
| 报表 | 指标口径、筛选、权限、脱敏、导出和更新时间 |
| AI 能力 | 输入来源、生成结果、人工确认、审核和禁止项 |

按本次相关性说明正常流程、空态、无资格、重复提交、外部失败、权限不足和撤销/回滚，并给出可观察的验收结果。来源未包含的接口地址、后端字段、角色和依赖不凭空补写。流程图与产品架构图分别按理解需要选择，验收可放在相关功能节或后续小节。
