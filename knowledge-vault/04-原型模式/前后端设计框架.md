# 前后端设计框架

本文用于指导“AI 生成原型”时的前后端对齐，不写平台技术实现细节，只给出可复用结构。

## 适配范围

- 活动与页面配置类需求
- 号卡/OAO、奖品券、素材库、报表导出、审核发布场景
- AI 辅助流程与工作流触发页

## 统一闭环（必须出现）

1. 用户端页面（展示、交互、异常态）
2. 配置模型（字段、默认值、校验、权限、状态）
3. 预览态（草稿可见）
4. 审核态（关键字段冻结与变更日志）
5. 发布态（上线、下线、回滚）
6. 统计态（产出、归因、审计）

## 字段语义契约

### 模块结构

- `moduleType`：模块/页面类型（活动页、报表、配置页、跳转页）
- `state`：`draft | preview | audit | published | suspended | rolled_back`
- `version`：配置版本号
- `changeSource`：变更来源（用户、AI、管理员）
- `operator`：操作人
- `riskLevel`：`low | medium | high`

### 配置对象（示例）

- `basic`
  - `name` / `startAt` / `endAt` / `province` / `channels`
- `content`
  - `title` / `banner` / `ruleText` / `materialRefs`
- `award`
  - `type` / `inventory` / `eligibility`
- `publish`
  - `previewRule` / `auditStatus` / `publishScope` / `rollbackPlan`
- `analytics`
  - `metrics` / `exportPolicy` / `auditLog`

## API 行为约束（原型生成提示）

- 所有字段更新应有 `changeReason`。
- 任何状态推进前都要有可回退前置条件。
- 发布前必须能在预览态看到变化。
- 状态为 `audit` 或 `published` 时，核心字段只能有受控编辑。

## 关键对齐规则（前端/后端一一映射）

- 用户端按钮文案、提示文案必须映射到后端 `publishState` 与规则字段。
- 所有异常提示必须有统一编码（如 `ERR_PREVIEW_TIMEOUT`、`ERR_PERMISSION_DENIED`），便于日志与回溯。
- 报表导出字段从 `analytics.metrics` 和 `permissions` 派生；避免在前端硬编码。
- 预览二维码/链接必须与正式发布参数集保持字段级一致。

## 原型生成要求（优先级）

1. 先输出后端字段结构（配置项），再输出前端页面映射。
2. 统一展示正常态、空态、异常态。
3. 显式标注审核、发布、下线、回滚行为。
4. 对涉及奖品/券/核销/外链的配置，显式放入风险字段。
