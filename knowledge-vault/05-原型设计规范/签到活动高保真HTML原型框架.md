# 签到活动高保真HTML原型框架

本页从 `贵州签到打卡.html` 这类 Axure HTML 原型中提炼可复用框架。生成签到、打卡、领积分、连续签到、任务积分活动原型时，必须优先复用本页的信息架构、字段密度、状态表达和前后台联动方式；不要只画一个移动端按钮页。

## 适用场景

- 签到领积分活动。
- 打卡赢奖品/经验值活动。
- 连续签到、累计签到、任务积分、满值兑奖类活动。
- 需要后台配置、前台预览、审核发布、权益/积分发放、数据报表闭环的活动。

## 页面框架

### 后台配置区

后台配置页必须体现运营真实配置密度。所有签到/打卡活动先实现以下核心分组：

| 分组 | 必须字段/控件 | 页面表现 |
| --- | --- | --- |
| 活动基础设置 | 是否测试活动、活动名称、活动时间、开始时间、结束时间、活动集、适用区域、用户范围、登录方式 | 表单分组展示，必填字段标记，保存/预览/提交审核操作固定可见 |
| 展示配置 | banner 图、背景颜色、海报开关、分享海报图片、页面配置、活动规则标题、背景图、规则背景图、规则背景色 | 采用上传占位、色值/开关、预览联动表达 |
| 签到/任务规则 | 签到项、启用状态、签到主按钮、自然日口径、每日次数上限、连续/累计进度、幂等规则 | 表格或独立任务卡表达，规则值、开关、次数和进度可评审 |
| 话术与异常 | 签到成功、今日已签到、未登录、无资格、额度或库存不足、发放失败、补偿中 | 成功、上限、资格和发放异常文案必须在原型中可见 |
| 用户范围 | 用户范围、目标用户来源、登录方式 | 明确参与范围和登录校验，不暴露内部人群规则 |
| 隐私与授权 | 隐私协议标题、隐私协议内容、同意授权控件、协议查看入口 | 没有真实协议时使用业务占位内容，不得省略授权状态 |
| 积分/权益设置 | 权益名称、权益类型、单次发放值、每日额度或库存、总额度或库存、次数上限、资损提醒 | 表格 + 表单组合，区分额度/库存、上限和风险提示 |
| 活动规则 | 自然日口径、参与条件、次数或累计规则、幂等规则、额度或库存规则、清零规则 | 规则列表或可编辑表格表达；不涉及清零时明确显示不清零 |

以下分组只在需求命中对应模式时增加，不得因为来源原型里出现过就强塞进所有签到活动：

| 按需分组 | 按需字段/控件 | 适用条件 |
| --- | --- | --- |
| 连续/累计任务扩展 | 任务一/任务二、标题图、上下标题、周期、连续中断、补签、启用状态 | 需求包含连续签到、累计签到、多任务或补签 |
| 跳转配置 | 站内页面、小程序、第三方链接、App 原生、奖品页、无跳转 | 签到按钮或任务完成后确有跳转；不写真实生产 URL |
| 奖品发放扩展 | 奖品名称、奖品类型、每日库存、总库存、失效时间、重复领取限制 | 奖励是实物、券或奖品，不是纯积分 |
| 满值/周期扩展 | 满值兑奖、奖品领取条件、周期计数、月度清零 | 需求包含满值兑奖、周期任务或月度重置 |

### 前台预览区

前台预览不能只是静态手机壳，必须展示用户能理解的状态：

| 状态 | 必须展示 |
| --- | --- |
| 首次进入 | banner、活动标题、规则入口、今日可得积分或权益、签到主按钮 |
| 可签到 | 立即签到、可签到、今日可得、积分、权益、当前次数、签到进度 |
| 签到成功 | 成功提示、积分或权益到账提示、今日已完成 |
| 已签到/达到上限 | 按钮置灰、今日已签到或已达上限、下次可参与时间 |
| 无资格/未登录 | 展示登录方式或不可参与原因 |
| 发放失败/稍后到账 | 展示稍后到账、补偿中或查看记录入口 |

### 报表与治理区

高保真原型必须包含报表或治理区，而不是只画前台：

- 筛选：活动时间、渠道、区域、用户范围、状态。
- 指标：访问人数、打卡人数、打卡次数、积分/经验值发放成功、发放失败、补偿中、库存消耗、资损风险。
- 明细：用户标识脱敏、打卡日期、打卡次数、奖励类型、发放状态、失败原因、补偿状态。
- 操作：导出、查看失败、补偿重试、下线活动。

## 高保真 HTML 要求

- 必须输出完整 `<!doctype html>` 单文件，包含内联 CSS。
- 必须有后台导航、顶部操作栏、表单分组、表格、状态标签、前台手机预览、报表/明细区。
- 必须体现上传位、开关、单选/下拉、数值步进或数字输入、主次按钮、异常提示。
- 必须有稳定布局和视觉层级：侧边栏/顶部栏/主内容/预览区或多列工作台。
- 必须使用平台业务风格：运营配置后台偏高密度、克制、可扫描；前台预览可以更活动化，但不能脱离后台配置。
- 禁止使用浏览器默认样式裸排版；禁止只输出 `<h1>`、`<input>`、`<button>` 的简单堆叠。

## 生成时必须继承的产品逻辑

```text
运营配置活动基础信息
  ↓
配置展示素材、任务、签到/打卡规则、奖品/积分权益
  ↓
配置异常文案、隐私协议和目标用户
  ↓
生成前台预览
  ↓
提交审核
  ↓
发布上线
  ↓
用户进入活动页并打卡/签到
  ↓
系统校验用户范围、登录方式、打卡次数、库存/额度
  ↓
发放积分/经验值/奖品或进入失败补偿
  ↓
报表复盘和异常处理
```

## 禁止事项

- 禁止把“知识库命中、模型补齐、联网资料、公开证据、工具日志、运行说明”写进原型画面。
- 禁止生成与本页字段和页面结构无关的通用 SaaS 页面。
- 禁止只展示前台手机页，不展示后台配置、审核发布和报表。
- 禁止写真实接口地址、真实账号、真实密钥或生产链接。
