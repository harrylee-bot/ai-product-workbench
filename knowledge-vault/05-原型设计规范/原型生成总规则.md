# 原型生成总规则

## 生成顺序

1. 判断活动类型和用户角色；
2. 读取产品架构和业务域；
3. 确定后台、前台和数据页面；
4. 列出对象、字段、状态和异常；
5. 画配置向导和主流程；
6. 补预览、审核、发布、下架和回滚；
7. 补空态、无资格、重复提交、失败和补偿；
8. 最后统一视觉、文案和交互。

## 高保真要求

- 使用真实业务字段和中文状态；
- 页面包含明确的布局、间距、表单、表格、按钮和状态标签；
- 活动配置页展示默认素材、上传/选择素材和清除行为；
- 审核和发布页展示状态、操作人、时间和下一步动作；
- 前台至少有一个成功态和一个失败态；
- HTML 原型不访问真实接口、不暴露真实凭据、不依赖远程脚本。

## 禁止项

- 只画一个没有后台配置的活动首页；
- 把审核通过直接等同于已上架；
- 省略奖品、库存、渠道、发展人和报表；
- 使用真实生产域名、账号、密码、Cookie 或 API key。
