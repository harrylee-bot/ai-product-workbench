# 产品进化方向判断规则

本页用于帮助 AI 基于知识库梳理产品进化方向。核心原则是：历史业务在原有基础上新增东西，新产品在既有产品框架中创新，不把每个需求都当作孤立页面。

## 需求类型判断

| 类型 | 识别信号 | 处理策略 |
| --- | --- | --- |
| 历史业务增量 | 用户提到已有页面、已有模板、某省需求、优化、新增字段、新增开关、新增筛选项、报表新增列。 | 先找对应业务域和历史案例，保留原对象、流程和状态，只增量补字段、规则、异常和数据口径。 |
| 能力平台化 | 多省、多模板、多活动、多渠道反复出现同类配置或同类报表。 | 抽象成模板、配置项、规则引擎、权限模型或报表口径，而不是单点硬编码。 |
| 风险治理补齐 | 涉及奖品、券、库存、核销、外链、个人信息、导出、权限、审核、日志。 | 优先补资损、安全、权限、审计、回滚、灰度和验收清单。 |
| 新产品创新 | 新用户角色、新工作台、新 AI 能力、新闭环、新跨模块流程。 | 先放入产品能力层，定义与活动、素材、奖品、报表、权限、审核、AI 助手的连接。 |

## 能力成熟度阶梯

```text
手工操作
  → 标准模板
  → 配置化能力
  → 审核发布闭环
  → 数据复盘闭环
  → AI 辅助生成
  → 智能推荐与自动优化
```

判断进化方向时，先看该业务域处在哪一阶，再决定下一步是补基础结构、补配置能力、补风控闭环、补数据闭环，还是引入 AI。

## 历史业务新增策略

历史业务新增时，AI 必须保留以下内容：

- 原有用户角色和权限范围。
- 原有活动、素材、奖品、报表或模板对象。
- 原有状态流转：草稿、预览、审核、发布、下线、回滚。
- 原有入口位置和信息架构。
- 原有报表口径和历史数据展示方式。

新增内容要明确：

- 新字段/新按钮/新筛选项属于哪个对象。
- 默认值、生效范围、历史数据兼容、空值展示。
- 对草稿、待审核、已发布、已下线活动的影响。
- 是否需要重新审核、是否影响报表、是否需要回滚。

## 新产品创新策略

新产品不是脱离原平台重新设计。AI 必须按以下顺序落位：

1. 确认新产品服务哪个角色：集团、平台、省市区、一线运营、审核人员、终端用户。
2. 确认新产品接入哪个能力层：素材、活动、奖品、渠道、报表、权限、AI 生成。
3. 确认是否新增核心对象：例如 AI 生成任务、活动码、审核任务、营销方案、智能推荐策略。
4. 确认复用哪些已有能力：登录权限、模板、素材、审核、发布、报表、日志。
5. 确认创新点：减少配置成本、提升复用、提升风控、提升归因、提升生成质量。

## 主要进化方向

| 方向 | 当前历史基础 | 下一步产品进化 |
| --- | --- | --- |
| 活动发布平台 | 模板选择、活动配置、审核发布、报表复盘。 | 从单活动配置进化为活动方案工作台，支持模板推荐、配置复用、差异校验和一键复制。 |
| 素材库 | 素材管理、专题标签、手机端制作、活动联动。 | 从素材存储进化为营销资产中台，支持素材引用影响分析、AI 搜索、素材质量评分和自动适配活动。 |
| 奖品与权益 | 奖品配置、库存、概率、核销、对账。 | 从奖品配置进化为权益风控引擎，统一资格、库存、发放、核销、补偿和资损评估。 |
| 渠道与一人一码 | 渠道编码、运营位、短链、企微、一人一码。 | 从链接工具进化为归因能力，统一生成、绑定、失效、追踪和复盘。 |
| 数据报表 | 活动报表、导出、大屏、运营统计。 | 从结果报表进化为决策洞察，支持异常提醒、渠道对比、模板效果分析和运营建议。 |
| AI 营销助手 | 案例库复制、Dify 工作流、长图/文案生成。 | 从内容生成进化为营销活动 Copilot，理解历史案例、生成配置建议、生成原型和复盘优化。 |

## 输出要求

当 AI 输出产品方案时，必须明确：

- 这是历史业务增量、能力平台化、风险治理补齐还是新产品创新。
- 继承了哪些已有对象、流程、页面和规则。
- 新增了哪些对象、字段、状态、权限、数据和风险控制。
- 本次变化对历史活动、历史素材、历史报表和已发布内容的影响。
