# 原型生成与历史复用策略

本页用于约束 Prototype Designer Agent 和 Prototype Code Agent：历史业务要在原有基础上新增，新产品要放在产品框架中创新。原型不是单纯画 UI，而是把业务对象、状态、字段、权限、异常和数据口径可视化。

## 生成前判断

| 判断项 | 历史业务增量 | 新产品创新 |
| --- | --- | --- |
| 输入特征 | 优化、增加字段/开关/筛选、某省需求、已有模板、已有页面。 | 新工作台、新 AI 能力、新闭环、新用户角色、新跨模块流程。 |
| 原型策略 | 保留原信息架构和页面路径，在对应区域新增控件、状态、校验和提示。 | 先映射到产品能力层，再设计入口、对象、流程、数据闭环。 |
| 必读知识 | 历史业务案例、原型资产映射、配置化页面模式。 | 产品架构、业务域逻辑、产品进化方向、前后端设计框架。 |

## 历史业务增量原型规则

- 不重画整个产品，不改原有导航和核心路径，除非需求明确要求。
- 新增字段必须放在对应字段组：基础信息、页面内容、奖品权益、跳转链路、数据统计、发布控制、运营治理。
- 新增开关必须展示默认值、生效范围、关闭态、开启态和历史数据兼容。
- 新增报表字段必须展示筛选区、明细表、导出、权限不足、数据延迟和空状态。
- 新增审核规则必须展示提交、审核中、通过、驳回、修改后再提交和操作日志。
- 涉及前台展示时，后台配置变化必须能在预览区或前台页面看到对应效果。

## 新产品创新原型规则

新产品原型必须至少包含：

1. 产品入口：它从首页、活动发布、素材库、案例库、报表还是 AI 助手进入。
2. 核心对象：例如营销方案、生成任务、素材组合、活动模板、渠道码、风险策略。
3. 主工作流：创建、配置、预览、审核、发布、复盘或生成、确认、发布。
4. 与既有模块关系：素材、活动、奖品、报表、权限、审核、AI 生成如何联动。
5. 数据闭环：生成结果、发布效果、渠道归因、报表指标和复盘建议。

| 活动发布/模板配置 | [[07-来源资产索引/旧版整理/04-原型模式/前后端设计框架/后台管理设计框架|后台管理设计框架]] + [[07-来源资产索引/旧版整理/04-原型模式/前后端设计框架/前台页面设计框架|前台页面设计框架]] | 草稿、预览、审核、发布、下线、失败。 |
| 素材库/专题/标签 | 后台列表、素材选择器、详情预览、审核详情 | 空素材、无权限、审核驳回、素材下线、引用影响。 |
| 奖品券/抽奖/核销 | 奖品配置、库存状态、领取/核销前台、对账报表 | 库存不足、重复领取、发放失败、核销失败、对账异常。 |
| OAO/号卡/商机 | 移动端预约页、门店/套餐选择、后台配置、商机报表 | 身份校验失败、门店为空、提交失败、订单状态回传。 |
| 报表/大屏 | 筛选区、指标卡、趋势图、明细表、导出弹窗 | 无数据、权限不足、导出中、导出失败、数据延迟。 |
| AI 助手/案例库 | 生成工作台、步骤进度、案例选择、结果预览、发布确认 | 生成中、生成失败、人工编辑、确认发布、回退模板。 |

## PrototypeSpec 输出要求

生成 PrototypeSpec 时必须包含：

- `pages`：后台页、前台页、预览页、审核页、报表页是否覆盖。
- `components`：列表、筛选、表单、状态标签、审核流、预览区、数据表、弹窗。
- `fields`：字段名、默认值、校验、生效范围、展示位置和数据来源。
- `states`：正常、空态、加载、失败、无权限、审核驳回、发布失败。
- `interactions`：配置变更如何影响预览，提交如何触发校验，导出如何受权限控制。
- `dataContracts`：接口不写真实地址，但要写清输入、输出、错误码和前端展示口径。

## 禁止事项

- 禁止只画单个漂亮页面，不表达后台配置、状态、异常和数据口径。
- 禁止新业务完全脱离既有产品导航、权限、审核和报表。
- 禁止历史业务增量时重构原有流程，除非需求明确要求。
- 禁止在 HTML 原型里访问真实接口或暴露真实 key、URL、账号。
