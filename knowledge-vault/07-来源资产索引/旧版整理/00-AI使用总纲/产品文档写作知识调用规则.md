# 产品文档写作知识调用规则

本页用于让 AI 识别“产品文档怎么写”。PRD 不是把用户口述扩写成长文，而是把业务逻辑、产品对象、流程状态、规则约束、数据口径和验收风险组织成可研发、可测试、可上线的文档。

## 写作前检索顺序

1. 先读 [[07-来源资产索引/旧版整理/00-AI使用总纲/产品架构与能力地图|产品架构与能力地图]]，确认需求影响哪一层能力。
2. 再读 [[07-来源资产索引/旧版整理/00-AI使用总纲/业务域到产品逻辑映射|业务域到产品逻辑映射]]，确认业务域对应的对象、流程和风险。
3. 如果是历史业务增量，读 [[07-来源资产索引/旧版整理/00-AI使用总纲/产品进化方向判断规则|产品进化方向判断规则]] 和对应案例。
4. 读 [[07-来源资产索引/旧版整理/02-规则约束/需求文档沉淀/需求文档通用约束|需求文档通用约束]]，补齐 PRD 必备骨架。
5. 按业务域补读资损、运营治理、AI/Dify、原型模式和案例。

## PRD 标准结构

| 章节 | 必写内容 | 常见缺失 |
| --- | --- | --- |
| 背景与目标 | 业务痛点、目标角色、现状问题、期望结果。 | 只写“新增功能”，没有业务目标。 |
| 范围与边界 | 本期做什么、不做什么、影响哪些端和模块。 | 没区分前台、后台、报表、权限和审核。 |
| 业务对象 | 活动、模板、素材、奖品、渠道、报表、AI 任务等对象定义。 | 没说明新增字段属于哪个对象。 |
| 用户与权限 | 角色、组织、省份、数据范围、审核角色。 | 只隐藏入口，不说明后端权限和导出权限。 |
| 主流程 | 用户端、后台端、审核端、数据端完整路径。 | 只有页面操作，没有状态流转。 |
| 配置与规则 | 字段、默认值、校验、生效范围、历史兼容。 | 忽略默认值、历史数据和存量活动影响。 |
| 异常与兜底 | 无权限、空数据、接口失败、库存不足、审核驳回、发布失败。 | 只写成功态。 |
| 数据与报表 | 指标口径、筛选项、导出字段、脱敏、审计、延迟。 | 报表字段和页面字段混在一起。 |
| 风险与资损 | 库存、资格、防刷、核销、外链、个人信息、回滚。 | 涉及权益但没有对账和补偿。 |
| 验收标准 | 按角色、状态、页面、接口、数据、异常、回归拆分。 | 验收只写“功能正常”。 |

## 按业务域补齐重点

| 业务域 | PRD 重点 |
| --- | --- |
| 活动发布 | 活动生命周期、模板类型、配置字段、预览审核、发布下线、报表复盘。 |
| 素材库 | 素材生命周期、专题标签、审核规则、引用影响、搜索筛选、历史兼容。 |
| 奖品券 | 库存、概率、资格、发放、核销、失败补偿、对账、资损评估。 |
| OAO/号卡 | 门店、套餐、订单、商机、发展人、渠道归因、接口失败和合规提示。 |
| 报表 | 指标定义、筛选条件、权限边界、导出审计、脱敏和数据延迟。 |
| AI 助手 | 输入输出 schema、来源案例、生成过程、模型/工作流边界、失败兜底、人工确认。 |
| 权限审核 | 角色矩阵、组织范围、审核状态、变更前后值、操作日志、越权处理。 |

## 历史业务增量写法

历史业务新增需求必须包含“继承与变化”：

```text
继承：沿用哪个历史业务、哪个页面、哪个对象、哪个流程。
新增：新增字段/入口/状态/规则/报表/权限。
变化：对历史活动、草稿、待审核、已发布、已下线、历史报表有什么影响。
兼容：历史数据怎么展示，空值怎么处理，是否需要迁移。
验收：新增能力和历史主流程都要回归。
```

## 新产品创新写法

新产品 PRD 必须先说明它在产品框架中的位置：

- 属于新工作台、新能力层，还是已有能力层扩展。
- 复用哪些已有能力：登录、素材、活动、奖品、审核、报表、AI 生成。
- 新增哪些对象：例如营销方案、AI 生成任务、智能推荐策略、归因任务。
- 如何与历史业务形成闭环：输入来自哪里，输出回到哪里，数据如何复盘。
