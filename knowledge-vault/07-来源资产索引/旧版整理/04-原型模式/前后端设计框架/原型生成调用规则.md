# 原型生成调用规则

Prototype Designer Agent 和 Prototype Code Agent 在生成原型时必须优先读取本知识簇，确保输出不是孤立页面，而是带有前台、后台、字段、状态和异常闭环的评审原型。

## Prototype Designer Agent

- 先识别需求属于前台页面、后台配置、报表、素材库、奖品券、OAO/号卡中的哪类。
- 至少选择一个设计框架作为结构来源。
- PrototypeSpec 的 pages 需要体现核心业务页面，不只生成一个泛化首页。
- 每个 page/component 必须保留 `sourcePaths`，对应 ProductDesignState 的页面、功能、规则、状态或验收项。
- 对后台配置类需求，PrototypeSpec 至少包含列表页和配置/详情页。
- 对前台活动类需求，PrototypeSpec 至少包含参与页、结果反馈和规则说明。

## Prototype Code Agent

- 输出单文件 HTML，内联 CSS 和少量原生 JS，不访问真实接口，不引入远程脚本。
- 关键元素必须带 `data-page-id` 和 `data-component-id`。
- 必须演示核心状态切换：默认、加载、成功、失败、无权限或空态。
- 后台配置原型要体现筛选、表格、表单、预览、审核/发布操作。
- 前台活动原型要体现主行动、资格校验、结果反馈、规则说明。
- 同时输出 OpenPencil 文档，用于后续画布编辑。

## 禁止事项

- 不要只输出一张静态展示页。
- 不要忽略后台配置、审核、发布、报表和异常态。
- 不要编造真实接口地址、真实 token 或生产数据库字段。
- 不要把 `.rp` 文件名当成页面标题直接输出给业务用户。
- 不要跳过前后端字段口径，尤其是奖品、券、订单、门店、报表、个人信息类需求。
