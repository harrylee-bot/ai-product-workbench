# 前台页面设计框架

前台页面用于用户参与活动、查看权益、提交信息、完成抽奖/签到/预约/领取等动作。来源主要包括签到打卡、抽奖、OAO、短链加粉、省份专项活动和终端长图类 `.rp` 原型。

## 标准页面结构

| 区块 | 必须包含 | 原型表现 |
| --- | --- | --- |
| 顶部品牌区 | 活动名称、活动时间、主视觉、适用省份/渠道 | 移动端首屏需要看到活动主题和主行动按钮 |
| 用户状态区 | 登录状态、参与资格、剩余次数、已领取权益 | 用状态卡或醒目标签展示，不能藏在说明里 |
| 主行动区 | 签到、抽奖、领取、预约、立即办理、分享 | 主按钮需要有默认、不可用、成功、失败四态 |
| 规则说明区 | 活动规则、参与条件、奖品规则、隐私提示 | 长规则可折叠，但关键限制必须前置 |
| 权益/奖品区 | 奖品名称、库存、发放方式、核销方式 | 奖品不足、已抢完、已领取要有明确状态 |
| 结果反馈区 | 成功弹窗、失败提示、重复参与提示、等待处理 | 反馈必须告诉用户下一步动作 |
| 底部辅助区 | 客服、常见问题、活动归属、投诉/隐私入口 | 涉及个人信息时必须展示必要说明 |

## 状态覆盖

- 未登录：提示登录或跳转登录，不展示可执行参与按钮。
- 不符合资格：明确原因，例如省份不符、名单不符、次数用尽、活动未开始。
- 可参与：主行动按钮可用，展示剩余次数、权益说明和关键规则。
- 处理中：按钮防重复点击，展示加载状态。
- 成功：展示结果、权益到账说明、下一步动作。
- 失败：展示失败原因、重试方式、客服或兜底说明。
- 已参与/已领取：按钮变为查看结果、查看权益或分享。
- 活动结束：保留规则与结果查询，不再允许新参与。

## 业务域适配

- 签到/打卡：必须展示连续天数、补签/断签规则、每日限制和奖励发放节奏。
- 抽奖/速抢：必须展示剩余次数、中奖结果、库存不足、概率/资格说明和发放失败兜底。
- OAO/号卡：必须展示号码/套餐/门店/订单状态，个人信息必须脱敏。
- 短链加粉/裂变：必须展示分享任务、邀请进度、防刷规则和统计口径。
- 终端长图/素材活动：必须展示素材预览、适配端、保存/分享动作和素材来源。

## 原型生成要求

- PrototypeSpec 需要把主行动按钮、用户状态卡、规则说明和结果反馈作为独立组件。
- HTML 原型必须演示至少一个成功态和一个失败态。
- 所有前台页面都要有 `data-page-id` 和关键组件 `data-component-id`。
- 不要只画静态海报页；必须体现用户状态、业务规则和操作反馈。
