## 知识库前端

用户最初要求：

- 后台知识库先做好。
- 使用开源项目 Obsidian 搭建知识库。
- 系统后续调用它的能力。
- 先把知识库搭建好，用户可以先维护知识库。
- 管理后台也接好。

后续明确：

- Obsidian 是本地知识库编辑方式。
- 线上前端页面使用 Quartz 社区开源方案。
- 需要能进入系统查看整个知识库。
- 系统调用知识库能力即可。

落地方式：

- 本地：Markdown Vault，可用 Obsidian 打开。
- 线上：Quartz 静态知识库页面。
- 系统：通过知识条目、双链和后端知识服务融合。

## Quartz 要求

- 使用 Quartz 最新可用版本。
- 页面中文。
- 支持 Markdown。
- 支持双链和关系图谱。
- 支持目录、搜索、暗色模式。
- 支持服务器重启后自动恢复。

当前线上效果：

- 首页标题为「AI Product OS 知识库」。
- 右侧显示关系图谱。
- 左侧显示搜索和目录。
- 知识条目可按目录浏览。

## 维护流程

```text
本地维护 Markdown Vault
  ↓
提交 Git
  ↓
同步服务器 knowledge-vault
  ↓
重启 Quartz 容器
  ↓
重新生成静态页面
  ↓
线上查看知识库
```

## 安全规则

- 不把服务器密码写入文档。
- 不把模型 API Key 写入文档。
- 不把 `.env` 写入 Git。
- 部署日志中避免输出敏感值。
- 知识库只保留配置说明和安全原则。
