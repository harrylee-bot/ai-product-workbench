# 06-三系统融合终极架构

本条目沉淀用户提供的 **AI PRODUCT WORKBENCH TRIPLE SYSTEM FUSION ARCHITECTURE**。这是项目的终极架构定位。

## 项目定位

系统是：

> AI Product Operating System，AI 产品操作系统。

核心由三大系统融合构成：

1. Constraint System，知识约束系统。
2. Decision System，决策系统。
3. Evolution System，进化系统。

## 强制原则

- 所有 AI 必须同时经过三系统。
- 任何决策必须有 Constraint 约束。
- 任何策略必须经过 Decision Engine。
- 任何优化必须经过 Evolution Engine。
- 所有结果必须可追溯。

## 总体架构

```text
User Input
  ↓
Constraint System
  ↓
Decision System
  ↓
Evolution System
  ↓
Orchestrator
  ↓
Agents
  ↓
Patch System
  ↓
Execution Engine
```

## Constraint System

路径：`apps/api/src/constraint/`

作用：

- 将知识转为行为约束。
- 过滤 AI 行为。
- 限制策略生成。
- 约束 Patch 执行。
- 控制 Decision Engine。

Constraint：

```ts
type Constraint = {
  id: string
  rule: "must_follow" | "prefer" | "avoid" | "warn"
  scope: "agent" | "decision" | "patch" | "qa"
  condition: string
  effect: string
  weight: number
  sourceKnowledgeId: string
}
```

ConstraintContext：

```ts
type ConstraintContext = {
  mustFollow: Constraint[]
  prefer: Constraint[]
  avoid: Constraint[]
  warn: Constraint[]
}
```

## Decision System

路径：`apps/api/src/decision/`

作用：

- 生成多个策略并选择最优。

Strategy：

```ts
type Strategy = {
  id: string
  name:
    | "conservative"
    | "balanced"
    | "aggressive"
    | "full_rewrite"
  description: string
  patchOperations: PatchOperation[]
  impact: "low" | "medium" | "high"
}
```

DecisionPlan：

```ts
type DecisionPlan = {
  strategies: Strategy[]
  selectedStrategyId: string
  reasoning: string[]
}
```

决策流程：

```text
User Input
  ↓
Intent Analysis
  ↓
Constraint Filter
  ↓
Generate Strategies
  ↓
Score Strategies
  ↓
Select Best Strategy
```

评分算法：

```text
score =
  usability * 0.25 +
  feasibility * 0.25 +
  businessValue * 0.3 -
  risk * 0.2
```

## Evolution System

路径：`apps/api/src/evolution/`

作用：

- 系统学习。
- 自我优化。

DecisionTrace：

```ts
type DecisionTrace = {
  id: string
  input: string
  strategies: string[]
  selectedStrategyId: string
  outcome: "success" | "failure" | "partial"
  metrics: {
    qaPassed: boolean
    userSatisfaction: number
    executionTime: number
  }
}
```

EvolutionSignal：

```ts
type EvolutionSignal = {
  strategyId: string
  signalType: "promote" | "demote" | "neutral"
  weightDelta: number
  reason: string
}
```

SystemPolicy：

```ts
type SystemPolicy = {
  strategyWeights: Record<string, number>
  agentWeights: {
    product: number
    ux: number
    tech: number
    risk: number
    growth: number
  }
  decisionBias: {
    riskAversion: number
    innovationBias: number
  }
}
```

进化流程：

```text
DecisionTrace
  ↓
Outcome Analyzer
  ↓
Signal Generator
  ↓
Policy Update
  ↓
System Optimization
```

## 三系统融合执行流

主流程：

```text
User Input
  ↓
Constraint System
  ↓
Decision System
  ↓
Evolution System
  ↓
Orchestrator
  ↓
Agents
  ↓
Patch System
  ↓
Execution
```

## Orchestrator 职责

Orchestrator 不再负责：

- 决策生成。
- 权重计算。
- 策略选择。

Orchestrator 只负责：

- 流程编排。
- 调用三系统。
- 执行结果整合。

## Patch System 融合

Patch 必须：

- 遵守 Constraint。
- 使用 Decision 结果。
- 被 Evolution 记录。

PatchPlan：

```ts
type PatchPlan = {
  strategyId: string
  constraints: ConstraintContext
  operations: PatchOperation[]
}
```

## Agent 系统升级

所有 Agent 输入必须变为：

```ts
type AgentInput = {
  userInput: string
  constraintContext: ConstraintContext
  decisionContext: DecisionPlan
}
```

## API 设计

Constraint：

- `POST /constraint/build`
- `GET /constraint/context`

Decision：

- `POST /decision/generate`
- `POST /decision/select`

Evolution：

- `POST /evolution/trace`
- `POST /evolution/apply`
- `GET /evolution/policy`

- DecisionTrace
- EvolutionSignal
- SystemPolicy
- Strategy

## UI 系统

必须显示：

- Constraint View
- Decision View
- Evolution View

UI 结构：

```text
Input
  ↓
Constraint Applied
  ↓
Strategies Generated
  ↓
Selected Strategy
  ↓
Evolution Impact
```

## 验收标准

- Constraint 必须影响 Decision。
- Decision 必须生成多策略。
- Evolution 必须记录所有结果。
- Policy 必须动态更新。
- Agent 必须受三系统约束。
- Patch 必须全链路校验。
