# 业务逻辑与 PRD/原型映射

本档将“业务域”直接落到“PRD 文档应该写什么 + 原型要画什么”。

## 映射总则（先对象后页面）

1. 先确认业务对象：活动、奖品券、素材、模板、商机、报表。
2. 再确认状态链：草稿、预览、审核、发布、下线、回滚。
3. 再确认异常态：无权限、库存不足、外链失败、接口超时、导入失败。
4. 最后确认产出：PRD 章节、页面元素、后台配置字段。

## 业务域到 PRD 的映射

### AI营销助手 / 案例库

- PRD 写法：
  - 明确入口（案例选择/终端选择/生成步骤）。
  - 写清 AI 工作流输入输出 schema 与失败兜底。
  - 明确审核节点（发布前确认）。
- 原型要求：
  - 页面上体现“案例库→参数化配置→生成预览”。
  - 外部模型生成过程不直接在页面暴露调用细节。

### 云溪活动 / 奖品券 / 抽奖

- PRD 写法：
  - 明确活动对象、奖品对象、核销对象与库存控制。
  - 产出发布流程和风险点（资损/审核/回滚）。
- 原型要求：
  - 前台重点校验：活动规则、领取/核销入口、异常提示。
  - 后台重点校验：奖品配置、审核链、报表导出权限。

### 号卡 / OAO / 商机单

- PRD 写法：
  - 先定义商机单生命周期与关键状态。
  - 把接口依赖与权限边界单列。
- 原型要求：
  - 页面展示应区分未提交、已提交、失败、待处理状态。
  - 后台支持按省份/渠道过滤与异常批量处理。

### 素材库与模板

- PRD 写法：
  - 明确素材输入规范、版本号、复用策略、失效策略。
  - 明确模板参数和预览校验。
- 原型要求：
  - 配置项与预览组件字段一一映射。
  - 模板变更可见并可回退。

### 数据统计与报表

- PRD 写法：
  - 定义口径、指标、导出范围、脱敏规则。
  - 定义权限角色与导出审核。
- 原型要求：
  - 报表图、列表、筛选、导出行为要覆盖常见失败态。
  - 与发布状态联动，避免历史版本口径混淆。

## PRD 与原型的最小一致性清单

- PRD 页面范围 = 原型页面范围。
- PRD 字段定义 = 后台配置字段。
- PRD 风险表述 = 原型异常态。
- PRD 验收标准 = 原型验证脚本。
- PRD 变更原因 = 原型变更日志。

## 复用命令

当需求涉及多个业务域时，用这条顺序拼接：

1. 先执行 `业务域识别`，
2. 再执行 `对象复用清单`，
3. 再执行 `新增字段清单`，
4. 最后执行 `发布闭环清单`。
