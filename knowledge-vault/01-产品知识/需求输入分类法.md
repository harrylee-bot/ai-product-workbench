# 需求输入分类法

需求输入分类法用于帮助系统判断用户说的一句话应该调用哪些知识、约束和案例。

## 需求类型

| 类型 | 触发词 | 系统动作 |
| --- | --- | --- |
| 新需求 | 做一个、搭建、生成、设计、上线 | 创建产品设计状态，生成多策略 |
| 优化 | 优化、改造、调整、升级、重构 | 读取现有状态和历史策略 |
| Bug/异常 | 报错、失败、打不开、不生效 | 优先触发风险和 QA 约束 |
| 后台配置 | 管理后台、配置、字段、权限 | 调用配置化页面模式 |
| AI 工作流 | AI助手、Dify、模型、Agent | 调用 AI 营销助手与 Dify 约束 |
| 合规资损 | 奖品、券、核销、资损、安全 | 提升风险权重并触发 Patch Preview |
| 报表数据 | 统计、导出、PV、UV、转化 | 校验权限、口径和审计 |

```json
{
  "requirementType": "new_requirement | optimization | bugfix | admin_config | ai_workflow | compliance | report",
  "businessDomain": "AI营销与智能生成 | 云溪活动平台 | 号卡与OAO流程 | 素材库与模板配置 | 奖品券与资损核销 | 数据统计与报表 | 安全测试与资损评审",
  "riskLevel": "low | medium | high",
  "knowledgeRefs": [],
  "requiredConstraints": [],
  "missingQuestions": []
}
```

## 缺失信息处理

当输入不足时，系统不要假装确定，应在 [[04-原型模式/执行路径流式展示模式|执行路径]] 中展示“已采用保守假设”。

必须追问或记录的缺失信息：

- 业务目标和成功指标。
- 影响端：用户端、后台端、接口、数据、权限。
- 是否涉及奖品、券、资损、个人信息或第三方跳转。
- 是否需要预览、审核、发布、回滚。
- 是否需要引用已有案例或模板。
