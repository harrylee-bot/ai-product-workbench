# 需求输入分类法

需求输入分类法用于判断一句需求应该参考哪些业务知识、历史案例和风险约束。

## 需求类型

| 类型 | 触发词 | 处理重点 |
| --- | --- | --- |
| 新需求 | 做一个、搭建、生成、设计、上线 | 补齐背景、目标、用户、范围、流程、验收 |
| 优化 | 优化、改造、调整、升级、重构 | 读取现有规则，区分存量影响和新增能力 |
| Bug/异常 | 报错、失败、打不开、不生效 | 优先定位影响范围、复现路径、回滚和验收 |
| 后台配置 | 管理后台、配置、字段、权限 | 调用配置化页面模式，明确字段和状态流转 |
| AI 工作流 | AI助手、Dify、模型、生成、长图 | 调用 AI 营销助手与 Dify 约束 |
| 合规资损 | 奖品、券、核销、资损、安全 | 提升风险等级，补齐库存、核销、对账和审计 |
| 报表数据 | 统计、导出、PV、UV、转化 | 校验权限、口径、脱敏、导出记录和审计 |

## 缺失信息处理

输入信息不足时，不要直接假设需求已经完整，应记录保守假设并补充待确认问题。

必须追问或记录的缺失信息：

- 业务目标和成功指标。
- 影响端：用户端、后台端、接口、数据、权限。
- 是否涉及奖品、券、资损、个人信息或第三方跳转。
- 是否需要预览、审核、发布、下线、回滚。
- 是否需要引用已有案例或模板。

## 处理顺序（优先链）

1. 先用 [[01-产品知识/产品架构与能力地图|产品架构与能力地图]]确定对象边界。
2. 再用 [[01-产品知识/产品进化与创新决策|产品进化与创新决策]]判断增量、平台化新增或创新。
3. 再用 [[01-产品知识/业务逻辑与PRD原型映射|业务逻辑与 PRD/原型映射]]输出产物映射。
