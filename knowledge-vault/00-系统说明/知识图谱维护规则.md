# 知识图谱维护规则

知识库维护的目标不是把资料堆进去，而是把资料变成可被 AI Product OS 调用的结构化知识。

## 新增条目规则

每篇新文档必须包含：

- frontmatter：`title`、`description`、`date`、`status`、`tags`、`aliases`。
- 适用场景：说明什么时候使用这条知识。
- 核心内容：规则、案例、模式或流程。
- 上游来源：这条知识从哪里来。
- 下游影响：它影响约束、决策、原型、Agent 还是 QA。
- 至少 3 个双链：连到首页、目录页和一个业务/约束/模式节点。

## 状态规范

| 状态 | 含义 |
| --- | --- |
| 草稿 | 刚记录，未确认结构 |
| 待整理 | 内容有价值，但需要拆分或补来源 |
| 已整理 | 可以被系统检索和调用 |
| 已维护 | 已连接图谱，并可作为核心节点 |
| 废弃 | 保留历史但不再主动调用 |

## 收件箱处理

[[99-收件箱/README|收件箱]] 只做临时存放。每周应把内容处理为：

- 产品知识：进入 [[01-产品知识/README|产品知识]]。
- 约束规则：进入 [[02-规则约束/README|规则约束]]。
- 案例沉淀：进入 [[03-案例库/README|案例库]]。
- 原型模式：进入 [[04-原型模式/README|原型模式]]。
- Agent 规则：进入 [[05-Agent知识/README|Agent 知识]]。

## 图谱检查清单

- 首页是否能通向新条目。
- 新条目是否有反向链接。
- 关键约束是否连接到使用场景。
- 案例是否连接到业务域和风险规则。
- Agent 条目是否连接到执行路径。
- Quartz 生成后右侧关系图是否出现新增节点。
