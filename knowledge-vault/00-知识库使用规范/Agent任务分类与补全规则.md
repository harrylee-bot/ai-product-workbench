# Agent任务分类与补全规则

## 任务分类

| 类型 | 识别信号 | 读取顺序 | 输出重点 |
| --- | --- | --- | --- |
| 既有能力调整 | 新增、优化、调整已有活动、模板、素材、奖品或报表 | 当前对象 -> 对应业务域 -> 增量规则 -> 案例 | 保持原流程和页面骨架，只增加必要字段、状态和规则。 |
| 全新能力 | 新模块、新角色、新闭环或跨业务能力 | 产品架构 -> 产品进化 -> 页面框架 -> 业务域 -> 案例 | 先确定能力归属，再补充端到端流程。 |
| 简短目标补全 | 只给出活动名称或一句结果目标 | 产品架构 -> 业务域 -> 案例 -> PRD/原型规范 | 补齐常见角色、字段、状态、异常和验收，并标出假设。 |
| 来源核验 | 明确要求文件、出处、原型或手册 | 来源索引 -> 对应主知识 | 只输出原件信息和可核对的内容。 |

## 最小补全范围

默认补全以下内容：

- 使用角色：平台管理员、集团/省/市/区管理员、店长、策划人员和参与用户。
- 活动基础：名称、标题、业务类型、活动集、开始/结束时间、测试标记。
- 活动规则：适用省市、用户范围、登录方式、参与次数、目标用户和白名单。
- 页面配置：Banner、背景、规则区、权益区、按钮、海报、悬浮入口和跳转链接。
- 运行流程：保存、预览、提交审核、审核通过、发布、下架、重新上架。
- 结果数据：访问、参与、中奖/领取、订单/商机、渠道、发展人和失败原因。

## 必须追问的情况

- 奖品、券、流量包或订单会产生真实资损。
- 需要跨省、跨组织或跨角色访问数据。
- 需要新增外部系统、回传接口、敏感信息或生产配置。
- 原始文件之间对同一字段、权限或状态给出不同定义。
