# 知识分层与冲突裁决

本规则是线上 Agent 使用知识库的总门禁。目录位置不仅用于整理，也决定知识是否能进入正式生成。

## 四个可用层级

| 层级 | 目录 | 作用 | 正式生成是否使用 |
| --- | --- | --- | --- |
| 现行规则 | `00`、`04`、`05` | 约束任务分类、PRD 结构、验收边界和原型生成方式。 | 必须使用。 |
| 核心知识 | `01`、`02`、`03` | 描述产品架构、业务对象、流程、状态、风险和演进策略。 | 必须按业务命中。 |
| 案例补强 | `06` | 提供相似实现、历史风险和复用方向。 | 需要时补充，不能覆盖前两层。 |
| 来源核验 | `07` | 保存旧版整理、操作手册、资产清单和原始文件线索。 | 仅在明确查来源时使用。 |

`99-收件箱` 是待整理区，不是可用知识层。里面的内容未经去重、核验和冲突检查，不能进入线上正式生成。

## 冲突裁决顺序

同一问题出现多个说法时，按以下顺序取舍：

1. 用户本轮明确要求，但不能越过安全、权限和合规边界。
2. `00` 的执行强规则，以及 `04/05` 的现行产物规范。
3. `01/02/03` 的现行产品与业务知识。
4. `06` 的历史案例。
5. `07` 的旧版来源和原始资料。

低层级与高层级冲突时，采用高层级；不得把旧版资料中的章节、字段或页面模式重新扩散到现行产物。若两个同层级现行文件冲突，停止使用冲突结论，在运行元数据中记录冲突，并向用户确认真正影响上线、资损或合规的部分。

## 三类信息必须区分

| 信息类型 | 判断标准 | 输出方式 |
| --- | --- | --- |
| 已核验事实 | 现行主知识明确描述，且无冲突。 | 可以直接作为产品现状或业务规则。 |
| 产品默认值 | 主知识允许采用的通用默认方案。 | 明确写成“默认”，并保留可配置或变更边界。 |
| 待确认事实 | 预算、库存、概率、成本、真实接口、监管、合同或用户专属策略等无法从现行知识确认的内容。 | 放入 assumptions 或待确认元数据，不用“待确认”填充核心正文。 |

## 检索门禁

- 普通方案、PRD 和原型：只召回 `00-06`。
- 查来源、出处、原始文件、导入记录、资产清单或旧版资料：可以额外召回 `07`。
- 查收件箱或待整理资料：只在用户明确提出时读取 `99`，且输出必须标注“未经整理，不可直接作为现行规则”。
- `_templates` 只用于人工建条目，不同步为线上知识。
- 引用必须至少保留标题、来源路径和摘要；不能只返回 `#1/#2` 这类不可解释标题。

## 知识入库完成条件

新资料从收件箱进入主知识前，必须满足：

- 已确认归属目录和业务域。
- 已去除账号、密钥、真实接口、个人信息和内部运维信息。
- 已与同主题现行知识去重并处理冲突。
- 已说明适用场景、触发条件、规则、异常、风险或产物影响。
- 已补标题、描述、状态、标签和关联知识。
- 已通过知识库审计、检索回归和线上 Agent smoke。
