# 知识分层与冲突裁决

## 信息分层

| 层级 | 判断方式 | 使用范围 |
| --- | --- | --- |
| 平台共性 | 多份手册共同出现，且覆盖活动创建、审核、发布或权限 | 可用于平台级方案。 |
| 模板规则 | 在某个活动类型或模板手册中明确出现 | 仅用于该模板或同类模板。 |
| 区域案例 | 文件名带省、市、区域或具体项目 | 作为案例，不直接升级为全局规则。 |
| 原型表达 | RP 或 HTML 中展示的页面、字段、文案和交互 | 用于原型参考，需与文字手册交叉确认。 |
| 待确认项 | 只有截图、单个文件、模糊文字或推断 | 输出时标记待确认。 |

## 冲突裁决顺序

1. 同一模板的配置手册优先于泛平台介绍。
2. 同一文件内的字段说明优先于目录或演示页标题。
3. 同一业务在多个来源中重复出现的内容视为共性候选。
4. 区域、项目和特定活动只影响对应范围。
5. 只在 RP/HTML 中出现、手册没有文字说明的内容保留为原型表现，不推导接口合同。
6. 无法裁决时保留两个版本的来源并提出确认点。

## 同一知识体系的增量融合

- 线上知识页面与本地 `knowledge-vault` 是同一知识库的发布版本和维护源，沿用原有主题路径。新增原件先按对象归入原主题，确有新的业务域时才扩展主题。
- 原主题保存可复用规则、适用版本和冲突结论；逐份审读页及 `storage` 台账是来源证据，使用“仅查来源”状态，不并行维护另一套正式规则。
- 新稿、技术设计、操作手册、原型和演示实现分别记录。时间较晚、文件后缀较大或标题相同均不足以自动判定替代关系；未裁决的冲突保留双方来源和范围。
- 文档编排、配图和样式沿用 [[04-产品文档规范/PRD标准结构|当前 PRD 标准结构]] 及本机 Codex 技能。历史材料的固定通用章节、接口示例和安全表勾选不能覆盖当前编写规范。
- 发布时仍通过项目既有知识构建与检索链路更新同一逻辑知识版本；保留已发布历史引用和项目权限边界，不新设独立知识入口，不将受限项目资料并入公共全局知识。
- 本轮只读核对的线上全局发布标识为 `workbench-1.0.0`、版本 `1`、状态 `ready`。本次候选继续沿用该逻辑 key；正式发布前需重新核对当前版本，再按原流程递增版本，不能覆盖不可变历史，也不能另取一个“本机知识库”key。
- 未获得发版指令前只修改本地维护源，不创建或切换线上数据库知识版本。

## 引用要求

每个业务条目至少保留：

- 原始文件路径；
- 文件类型或模板名称；
- 归纳出的对象、流程、字段或状态；
- 适用范围；
- 需要验证的事项。
