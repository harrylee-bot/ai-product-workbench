# 知识库使用规范

## 内容层级

| 层级 | 目录 | 用途 |
| --- | --- | --- |
| 产品主知识 | `01-产品架构`、`02-业务域知识` | 输出产品方案、流程、字段和规则。 |
| 设计与交付规则 | `03-产品进化规划`、`04-产品文档规范`、`05-原型设计规范` | 输出增量方案、PRD、原型和验收要求。 |
| 可复用案例 | `06-案例库` | 按真实活动和区域案例补充方案。 |
| 原始来源 | `07-来源资产索引` | 定位 PPT、DOC、RP、HTML 原件，不单独替代产品判断。 |

## 基本原则

1. 先判断需求改变的对象，再读取对应业务域。
2. 原始文件的明确字段、页面和操作步骤可以作为事实依据。
3. 多个文件的共同内容可以整理为平台共性，但必须保留来源范围。
4. 单个区域或单个模板的做法只能作为案例，不能自动扩展成全平台规则。
5. 原始文件之间出现差异时，优先确认适用模板、业务类型、区域和文件时间。
6. 未在原始文件中确认的接口、错误码、后端字段和权限细节标为待确认。

## 输出边界

- PRD：说明角色、目标、流程、字段、状态、异常、权限、数据和验收。
- 原型：覆盖配置、预览、提交、审核、发布和用户端关键状态。
- 方案：说明复用的模板、素材、奖品、渠道、活动集和报表能力。
- 来源核验：给出原始文件路径和文件类型，不把截图或推测写成正式规则。
