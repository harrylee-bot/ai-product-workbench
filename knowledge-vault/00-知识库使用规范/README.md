# 知识库使用规范

本页定义 AI 使用知识库的顺序。目标是避免只命中零散历史文档，而忽略产品架构、业务域逻辑和产品进化方向。

## 执行模式

Agent 在执行前必须先按 [[00-知识库使用规范/Agent任务分类与补全规则|Agent任务分类与补全规则]] 判断需求模式：

| 模式 | 核心要求 |
| --- | --- |
| 历史项目增量 | 先继承当前项目和历史原型，再增加新字段、新状态、新页面区块或新规则。 |
| 全新功能 | 可以重组页面框架，但必须落回产品能力地图和平台通用能力。 |
| 一句话需求补全 | 用产品架构、业务域知识和历史案例补全用户没说的信息，高风险事实才追问。 |

## 检索优先级

1. 主知识优先：`01-产品架构`、`02-业务域知识`、`03-产品进化规划`、`04-产品文档规范`、`05-原型设计规范`。
2. 案例补强：`06-历史案例库` 用于找相似业务和历史风险。
3. 来源核验：`07-来源资产索引` 用于确认资料来源、文件清单和旧版整理。
4. 收件箱只作为待处理资料，不参与正式生成。

## 禁止事项

- 禁止只读取来源资产清单就生成 PRD 或原型。
- 禁止把单省历史需求当作通用产品架构。
- 禁止把新产品设计成孤岛，必须说明接入哪个能力层。
- 禁止历史业务增量时重构原流程，除非需求明确要求。
- 禁止一句话需求直接要求用户补全所有细节；应先用产品架构和历史知识补全常规信息。
- 禁止在原型中暴露真实接口地址、密钥、账号或内部运维信息。
