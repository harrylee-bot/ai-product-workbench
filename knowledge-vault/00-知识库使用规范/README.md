# 知识库使用规范

本页定义 AI 使用知识库的顺序。目标是避免只命中零散历史文档，而忽略产品架构、业务域逻辑和产品进化方向。

## 项目知识边界

在本项目对话中，用户提到“知识库”“同步到知识库”“同步到项目”时，默认指本仓库内的 `knowledge-vault`、项目数据库知识库和项目本地 `storage` 归档，不指任何外部知识库。除非用户明确给出外部平台、链接或授权要求，Agent 不应把资料同步到外部平台。

## 执行模式

Agent 在执行前必须先按 [[00-知识库使用规范/Agent任务分类与补全规则|Agent任务分类与补全规则]] 判断需求模式：

| 模式 | 核心要求 |
| --- | --- |
| 既有对话增量 | 先继承当前对话里的既有产物和历史原型，再增加新字段、新状态、新页面区块或新规则。 |
| 全新功能 | 可以重组页面框架，但必须落回产品能力地图和平台通用能力。 |
| 一句话需求补全 | 用产品架构、业务域知识和历史案例补全用户没说的信息，高风险事实才追问。 |

任何任务都必须同时遵守 [[00-知识库使用规范/知识分层与冲突裁决|知识分层与冲突裁决]]，先确定可用知识层，再处理冲突和不确定信息。

## 执行过程可见边界

Workbench 对话区可以展示 Agent 过程、执行清单、工具调用与事件、产物变化，但只能沉淀这些低噪声事件：

- 步骤级事件：任务理解、知识检索、方案生成、PRD/原型生成、校验、收尾。
- 工具级事件：文件读取、知识库检索、原型生成、导出、外部工具调用的开始/完成/失败。
- 授权或确认事件：需要用户确认、补充、授权、选择或审阅的节点。
- 产物级事件：PRD、Canvas、原型、导出文件等可见产物的新增、更新、失败。
- 错误级事件：阻塞错误、可恢复错误和明确的降级说明。

不得把 token chunk、模型流式碎片、`message_delta`、checkpoint、runtime 内部状态、隐藏推理或调试元数据当作用户可见步骤、工具事件、产物变化或高优先知识沉淀。

## 检索优先级

1. 主知识优先：`01-产品架构`、`02-业务域知识`、`03-产品进化规划`、`04-产品文档规范`、`05-原型设计规范`。
2. 案例补强：`06-历史案例库` 用于找相似业务和历史风险。
3. 来源核验：只有查询明确包含来源、出处、原始文件、导入记录或旧版资料意图时，才检索 `07-来源资产索引`。
4. `99-收件箱` 不同步为线上正式知识，不参与 PRD、原型或方案生成。

## 禁止事项

- 禁止只读取来源资产清单就生成 PRD 或原型。
- 禁止把单省历史需求当作通用产品架构。
- 禁止把新产品设计成孤岛，必须说明接入哪个能力层。
- 禁止历史业务增量时重构原流程，除非需求明确要求。
- 禁止一句话需求直接要求用户补全所有细节；应先用产品架构和历史知识补全常规信息。
- 禁止在原型中暴露真实接口地址、密钥、账号或内部运维信息。
